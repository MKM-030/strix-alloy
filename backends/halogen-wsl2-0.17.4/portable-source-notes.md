# 0.17.4 source lineage and limits

The baseline is the current `backends/halogen-wsl2-0.17.3/profiles/sources.json` membership. Only those source files were derived; no baseline `.local`, credential, installation, run, trial or STATE data was copied. Version/profile/library/probe identifiers are rebound by exact substitutions. The HIP probe is renamed `halogen0174_hip_probe.c`. Exact per-file baseline/prepared byte counts and hashes are in the parent preparation's `source-transformations.json`.

The five bridge patch files and `scripts/bridge_adapter.py` were replaced with byte-identical derivatives from the separately sealed `halogen0174-seam-map-20261010`. Their independent finite source review covers eight functions, 7573 bytes, complete function hashing, relocation normalization, referenced literals, BSS alias geometry and the existing register/frame contract. It does not prove the semantic ABI of the two indirect callbacks, exceptions/asynchronous unwind through the inserted call, HIP loader behavior, planner execution or one-phase v2 runtime registration. No experimental engine addresses are imported.

The new entrypoint adapter binds the complete extracted upstream entrypoint. Source authoring preserves the bytes preceding/following the native host_preflight, renames that function, then inserts the retained WSL wrapper. Python source newlines for that literal are normalized to LF. The preview has SHA `2996f76ee77fe3f2de862fe855eabb512581075a4f4cdbdaebee32825af3c5c1`; its service preview replaces exactly five API paths and has SHA `dd65627e1609327951372c17b71f91bbb49386968c4a507c71191a000573777a`. Root must run the actual adapter and require these byte identities.

The bearer wrapper retains its comparison, duplicate-header rejection, 401 response and token shape; only its complete upstream API pin changes. The official API remains unmodified. Its matched `request_records.py`, `tool_parse.py` and `halogen_tools.py` are retained as private extracted artifacts. Native API-key options are not set by the candidate; root must preserve that environment assumption and retain the invalid-token probe. New frontend-only API-key and `HALOGEN_TOKENIZE_REUSE` filtering is preserved because all non-preflight entrypoint bytes remain intact. Rendered-chat token-prefix reuse is a separate stock API default; the frozen raw-completions request bypasses it, and prompt cache remains Off.

The controller derivative adds only the new backend directory to three existing allowlists and one rejection-message version list. It preserves the 0.17.2/0.17.3 entries needed for restoration. The normal profile changes only the backend directory/token path and expected API/engine version. Release/source manifests and this documentation are authored afresh instead of carrying historical qualified flags or compiled hashes.

The four root CPU products use the retained GCC 13.3 recipe. The w4b DSO is built only because the ordinary installation recipe expects it; this preparation grants no w4b runtime qualification. `build_normal_bridges.ps1` compiles into a new preparation child and records fresh inputs/commands/outputs. `finalize_cpu_pins.ps1` updates only the inactive source release/source manifest after validating that receipt, while leaving runtime/production flags false. The finalization receipt records before/after hashes; the original preparation seal remains historical evidence. The ordinary installer subsequently performs its own exact-byte extraction/rebuild verification at the deployed layout; this intentional small repeated build does not rehash or download models.

The package contains retained historical diagnostic sequence sources. They are not rebound runtime evidence and are not a normal-v2 qualification requirement. Existing model/lookup/tokenizer receipts must pass the established identity-reuse gate. Do not rehash unchanged huge checkpoints, relax reserve/totals checks, enable historical optional tuning receipts or infer a performance gain from this source preparation.
