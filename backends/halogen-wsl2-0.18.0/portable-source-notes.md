# Source lineage and current scope

Source membership derives from the 0.17.4 package manifest, excluding .local, installations, credentials and runtime receipts. Version/profile/library/probe identifiers are rebound to 0.18.0. Engine, entrypoint, API, header and CPU-output hashes come from the freshly pinned official image and retained GCC 13.3 recipe. The bridge C changes only its version identifiers, complete engine hash and exact RVA; the trampoline's frame/register contract is unchanged. The adapter binds the new ELF size, function range/hash, instruction signature and source hashes.

The fresh finite map covers the enclosing demand function and seven direct helpers, including normalized instructions, references/imports, branch geometry and CFI. Indirect callback implementations and normal HIP/model serving remain outside that static map. A fresh no-device CPU provider inspection establishes the actual dladdr/export and mapped loader closure for this image; it does not execute GPU calls or the engine.

The bearer wrapper and typed defaults retain their implementation while the complete upstream API pin changes. The entrypoint adaptation retains all non-host_preflight bytes and changes exactly five service API launch paths. The normal settings and established huge-asset identity-reuse policy remain unchanged.

Post-build source finalization changes documentation, Python comments, the absolute WSL launcher path and the empty bounded-sequence hash. The compiled C, assembly, probe and header inputs remain byte-identical to the completed CPU build receipt. Exact before/after identities are recorded in source-finalization.json; four compiled products need no rebuild for these source-only corrections.
