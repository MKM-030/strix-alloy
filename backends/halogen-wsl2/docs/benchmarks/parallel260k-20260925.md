## Three full contexts: host freeze

**Failed host-stability test. Do not repeat this configuration.** A later, separate attempt requested three 262144-position slots (786432 total, approximately 21.6 GiB KV). It never reached readiness and started **zero requests**: no prefill or decode rate exists.

The 12 GiB Windows-available stop threshold triggered at 18:47:19.868827 UTC, with a reported minimum of 11689648128 bytes. Available memory continued falling while the guard tried to stop the exact container, reaching **651264 bytes** in its samples. The stop command timed out after 30 seconds at 18:47:50.743298 UTC. Native logs continued reporting KV reservation; no final outcome or verified container stop was recorded.

The owner reported a frozen PC and performed a hard power-off and reboot. Windows boot time was 19:23:38 UTC; events 41/6008 confirm an unclean shutdown, **not its underlying cause**. Memory collapse and failed cancellation during KV reservation are observed; a specific driver/kernel fault is not established. The earlier guarded three-context attempt that recovered without reboot is a separate test, not evidence that this later run stopped safely.

The container limit and asynchronous memory guard did **not** protect the host on this allocation path. The 12 GiB setting is not a hard reservation or safe recommendation. Three-full-context retries are stopped pending a separate safety redesign. No three-full-context profile is shipped, and the successful two-full-context lab profile is also not installed by the public launcher. No model was restarted after this incident to prepare this publication.

[Sanitized incident record](triple260k-freeze-20260925.json) preserves the guard samples, source hashes, failure times and missing-cleanup classification. Run `20260925-184528-96e3386cf8ef4b699bb4eda220e92e72`.

## Interpretation

Synthetic repeated filler and deterministic marker checks demonstrate request completion, not retrieval accuracy across 260k or a long-duration stability guarantee. MTP acceptance depends on workload. The owner reports **9 GB Windows idle RAM usage** and a responsive desktop; these observations are distinct from instrumented free memory under load. Gaming with this WSL profile remains untested.
