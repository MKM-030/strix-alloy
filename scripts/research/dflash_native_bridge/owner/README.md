# Owned pending-prefill and committed decode capture

This private component implements the missing pending-holder → materialized native record → Request ownership path and a bounded target-feature capture queue for the pinned Halogen 0.17.3 runtime. It is default off. Its C++ CPU component is built and exercised offline; it does not install relays, load HIP, allocate accelerator memory, initialize a provider, execute Halogen, send requests, download models or modify serving/lifecycle state. Root owns the executable relay installation and transport integration.

The runtime SHA256 is `af4f07bbe3759206013eb6f1328095ca2105cfda5127c5b9a2ab93e1aea987b7`; the supplied disassembly SHA256 is `1c7ace3b584ec57139b052413381522a414c6d012d93da237dc4d5942f8a7f73`. `qualify_cpu.py` checks these complete files and its cited instruction spans against the ELF through the existing passive parser, then compiles a portable component and a bounded CPU harness in this folder. `cpu-source-receipt.json` records the exact component, dependency and harness hashes and actual process completion.

`pending_owner.h/.cpp` owns a unique session/ticket/lease/cache generation and copies the complete prompt IDs into cold-provided storage before first prefill. Admission requires the actual native `aggregate+8 == null` Cache Off predicate, one selected native slot, Request-backed mode 1, the selected current slot, exact loaded pins and ordinary greedy unconstrained text. Native callbacks borrow the supplied frames and native source addresses only for the invocation. No borrowed native vector, HC pointer or frame survives a callback.

`native_adapter.h/.cpp` maps the pinned native frames to this owner. A prompt chunk starts at holder `+0x410`, uses the copied full input vector at `+0x38`, and has the native count carried in R13. Model `+0x2e8` must equal the absolute chunk start before forward and the completed chunk end afterward. Missing/duplicate taps, wrong positions/counts, callback loss and copy/fence failures disable external feature availability while retained slot quarantine remains authoritative.

The successful ownership handoff needs the intermediate `Materialized` state: the native record-move helper at `0x1747c40` moves the pending record, then caller `0x173d3d7` destroys the holder **before** successful Request construction. A materialized holder destructor clears its live lifetime without retiring the pending ticket. Both successful-birth hooks join only a materialized ticket with exact wire/model/slot/cache generation, Request-backed mode and every copied prompt ID. `retained_lease_bridge.h` uses the separate `hgn_dflash::Lane` ABI; transfer additionally requires the controller's completed actual null-cache reset for that same newly armed generation. Cancellation before materialization retires only the pending owner; Request destruction retires only the exact Request allocation/birth. Quarantine persists through either retirement.

Prefill can terminate at EOS or its output ceiling before any Request is constructed. The native record destructor at `0x17466e0` explicitly abandons an exact still-materialized ticket, checking copied prompt IDs/wire/slot/mode. The separate retained `retire_materialized` operation moves that unborn owner to quarantine; this does not change the normal materialized holder-destructor exemption. A record destructor after successful Request transfer leaves the Request lease alive.

Destruction is deferred rather than discarded when the owner's nonblocking lock is busy. Separate atomic generation records retain pending-holder cancellation, the exempt materialized-holder lifetime end, exact Request death and materialized-record abandonment. The abandonment callback compares every native prompt ID against the stable copied IDs while the native record remains alive; only the proved generation is queued. A short publication guard prevents copied identity/ID storage from being rewritten during that proof. Queued pending cancellation remains cancellation if materialization or transfer progresses before it drains. Successful entry and exit drain these records, including admission and transport polling; stale or foreign generation records cannot modify the current owner.

`LeaseOps::retire` and `abandon_materialized` now return a disposal acknowledgement. A false result retains the complete copied `Binding` and retirement kind inside Owner and retries through the bridge on later successful entry/poll. New publication and storage reclamation remain blocked until acknowledgement, copy-fence completion and exact borrow release. A busy retained Lane can therefore delay retirement without losing it. The bridge checks the complete retained identity, acknowledges an already disposed older generation without writing a newer lane, and rejects a foreign current/future binding. Its generation and shared-round reads use the frozen controller's `atomic_load` operations. Integrators must update any custom LeaseOps functions to this boolean acknowledgement ABI.

A successful retired-owner reclamation poll additionally closes admission to new identity readers and requires every existing full-ID proof reader to unpin. This does not assume serialized native callbacks. A later publication reopens reader admission only after it has copied the next prompt and identity. Final shutdown must call `disable_new()` before freeing cold storage after a successful reclamation poll, so another publication cannot reopen it.

HC capture uses actual native boundaries `[4,16,24,36,44]`, corresponding to trained teacher taps `[3,15,23,35,43]`. At `0x17f22c4`, R14 is Model, EBX is native layer and EBP is row count; source Model `+0x948` contains native BF16 width 2560. The ordinary HC call at `0x17f22bc` falls through this seam. The profiled HC call at `0x17f2658` joins it through `0x17f2689`. Copies happen here before attention and the FFN HC call at `0x17f244c` reuse the same source buffer.

`hip_copy_backend.h/.cpp` adapts cold-resolved HIP function pointers. Each tap queues a pitched same-stream D2D copy into independent cold-provided staging: source pitch 5120 bytes, destination pitch 25600 bytes, row width 5120 bytes, tap offsets `0,5120,10240,15360,20480`. The final layout is row-major BF16 `[R,12800]`, in the trained tap order. This is full concatenation with no averaging, lossy width reduction or raw 10240-wide substitute. The selected native stream is zero; native stream ordering must be proven and `NativeProof.default_stream_verified` must be explicitly admitted by the cold integrator. No capture hook synchronizes or waits. A completion event fences all queued copies before external publication; the copied destination remains independent when native HC is overwritten. Native BF16 HC is an approximate draft input compared with the original teacher's FP32 HC path; native target verification and recurrent commit remain authoritative.

`decode_capture.h/.cpp` has eight cold-provided independent staging slots, each for at most four feature rows and a distinct event. `native_decode_adapter.h/.cpp` captures native verification inputs `[current,d1,d2,d3]` at `0x173fe32`, records the copy fence after forward returns, reads the native authoritative committed count from ESI at `0x173fea0`, and confirms the model position at `0x173fea5`. Only first `k=a+1` processed input rows are publishable. Scalar fallback at `0x1740488` contributes one input row and its native completed position at `0x174048d`. Common outcome `0x17411fb` must report continuing status 0 and exact native transported-token delta `k`; partial output, stop/EOS/cancellation/errors/loss never publish a continuing feature update. The correction/bonus is carried as `next_current`; it is an unprocessed ID with no verified hidden row. Speculative suffix IDs are zeroed in the view. Queue saturation invalidates external feature continuity and preserves scalar quarantine.

The decode adapter obtains its transaction round through `RoundSource`, concretely `RetainedLeaseBridge::rounds()`. It consumes the controller's round assigned once by mandatory native Entry dispatch, including scalar/provider-unavailable paths. It has no independent counter and does not infer acceptance, round identity or positions from output text.

Decode retirement marks exact-generation atomic slot records before attempting its nonblocking lock. Its next successful entry/exit finishes matching slots, records any missing copy fence and clears matching active work while keeping outstanding borrows intact. Retirement racing admission or fence polling cannot publish a feature view. Each atomic record reserves its high bit for retirement; decode feature admission therefore fails closed for lease generations `>= 2^63`, while the separate retained controller and pending owner retain their full 64-bit generation ABI. This practical exhaustion bound does not release or alter the retained native lease.

Tentative decode admission has a separate retirement record. Only a successful admitted capture updates the current generation and last admitted round. A rejected foreign binding therefore cannot erase current round history or redirect loss attribution; completing round 10, rejecting foreign generation `g+1` round 1, then replaying round 10 for `g` remains a rejected duplicate.

The transport lifetime is explicit:

1. `Owner::acquire_features(FeatureView&)` succeeds after materialization, exact Request transfer and capture-fence completion. Positions are `0..rows-1`. It borrows **independent owner staging**, never native Model `+0x948`.
2. `DecodeCapture::acquire(DecodeView&)` borrows the FIFO front after its capture fence and native continuing output. Transport copies exactly `committed_rows * 25600` feature bytes; copied IDs and positions are the first `committed_rows` IDs and `anchor + row`.
3. Root transport queues D2H into its own pinned host payload, waits by nonblocking polling outside native hooks, copies IDs/binding metadata into that payload and retains the staging borrow until its D2H completion event finishes. No device pointer goes to the provider or across transport.
4. Transport releases the prefill borrow with the exact `binding.ticket`, or the decode borrow with the exact `capture_sequence`. Wrong acknowledgements are rejected. Prefill staging cannot be overwritten until borrow release, owner retirement and capture-fence completion. A decode slot cannot be reused until exact release. Failed event record/query permanently pins uncertain storage until process exit; disabling collection does not make an in-flight buffer reclaimable.

Root must install state-preserving relays at every lifecycle/capture/commit seam, replay displaced instructions/calls/branches, and retain unconditional integer suppression at both post-SETE flag joins in addition to the controller Entry/Prepare/PostReset gates. Those mandatory gates must run even when an optional collector is disabled, busy, loses a source record or fails stack admission. Root must supply cold pin/text/slot/stream admission, the actual fresh-reset evidence, lifetime-pinned storage/events/functions, native provider transport and the controller's immutable request/generation/round binding. Consequently `installed_native_relays` and `live_capture_exporter_complete` remain false in this component receipt. CPU success proves these source components and their bounded ownership semantics; it does not establish a live capture, drafter acceptance or serving speed.
