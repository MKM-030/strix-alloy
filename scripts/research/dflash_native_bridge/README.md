# DFlash native bridge: source and CPU qualification archive

This package preserves the frozen pending-owner/decode-capture, retained-controller/cold-installer and worker-owned transport source snapshots. It is **source/CPU qualification only**, **default off**, and supplies no native installation, accelerator execution, provider scheduling, drafter acceptance or serving gain. No executable/native binaries, model weights or standalone process logs are included. The one included binary data file is the explicitly authorized synthetic host CPU wire fixture, `transport/cpu-wire-fixture.bin`.

The copied source files are byte-for-byte originals. The original component READMEs, qualification receipts and delivery seals are retained as historical evidence. Their successful CPU checks were performed before this publication task; publication performs hashes and Python syntax checks only. The copied receipts contain hashes of earlier binaries that are intentionally absent here.

`source-provenance.json` inventories every copied file with its original absolute and repository-relative path, byte count and SHA256. It also hashes the two package-created files. The manifest itself is the only file excluded from its own hash inventory. `python -B verify_source_package.py` verifies the package inventory, byte hashes, JSON syntax, Python AST/import syntax and frozen source/receipt pins using Python's standard library. It does not import the copied helpers, execute their top-level code, compile C++, launch WSL, load native libraries or initialize a tensor runtime.

The frozen transport delivery seal and qualification receipt are pinned in `source-provenance.json`. Its copied CPU fixtures use host function-table stubs and a fake provider/tensor adapter. The receipt records zero-exit commands and no HIP loading, hardware initialization or native installation; no numerical or native tests are performed by publication or the package verifier. The package is ready for root review only when the manifest's `publication_state` says `ready_for_root_review`; a pending transport review leaves it incomplete.

The passive parser comes from the original `static-compatibility-audit` directory. The narrow native capture spans, native seam metadata, source relay disassembly and source FDE evidence are included. The complete 30 MB native disassembly is an external pinned input, alongside the native ELF; neither is needed for the package's static verification.

The original helpers retain their original relative paths and tool choices. Run them only in a separate scratch reproduction tree, because they generate files beside themselves and overwrite qualification receipts. To reproduce the existing qualification rather than modify this archive:

1. Copy `owner/` into scratch directory `dflash-prefill-owner-20261009/`, `controller/` into sibling `dflash-retained-controller-20261009/`, and `transport/` into sibling `dflash-owned-transport-20261009/`. These names preserve the unchanged bridge and transport include/build paths.
2. Copy `controller/passive_elf_review.py` into sibling `static-compatibility-audit/passive_elf_review.py`.
3. Independently supply the original pinned native ELF as `updates-20261009-0202/runtime-data/usr/local/bin/flash_serve.data` and full disassembly as `native0173-phase-clock-20261009/current-text.txt`, beneath the same scratch parent. The ELF SHA256 is `af4f07bbe3759206013eb6f1328095ca2105cfda5127c5b9a2ab93e1aea987b7` (26,188,824 bytes); disassembly SHA256 is `1c7ace3b584ec57139b052413381522a414c6d012d93da237dc4d5942f8a7f73`; parser SHA256 is `671297d02e798107827e5b51def19a288479a8c733c41b2221854bc96af9eddd`.
4. The owner helper expects Windows `wsl.exe`, Ubuntu-24.04 and a C++20 `g++` toolchain. The controller helper expects Clang, LLD, llvm-objdump and llvm-objcopy; its `--tool-bin` option overrides the historical ROCm 7.2 tool directory. Its instruction smoke is a Windows host fixture with two Linux FS-to-Windows GS TLS prefix adaptations. The unchanged transport helper expects the recorded Windows Clang/LLD tool path and Python; its source/reader tests depend on the frozen owner sibling. Linux FS/unwind behavior, Linux transport compilation and the native installer were not executed by this qualification.
5. Only an independently authorized CPU qualification run should execute `python -B qualify_cpu.py` or `python -B build_qualify.py` in those scratch directories. The package verifier never invokes them.

Reproducing toolchain output does not guarantee identical binary hashes across compiler/platform versions. Full passive qualification requires the independently supplied pinned ELF and disassembly. Copied raw receipt/evidence bytes, including their recorded line endings, must be preserved when publishing; verify Git's staged bytes separately before staging or committing.

The transport source includes worker-owned export that holds staging borrows through D2H completion and exact release acknowledgments. Live work still requires complete lifecycle/capture relays, actual Linux/HIP transport and pinned-memory behavior, native stream and stack admission, retained ownership pins, causal provider/Ready coordination and root-controlled runtime validation. The source includes default-off cold-installer code for review; this archive does not invoke it. Optional collection failures retain quarantine and scalar behavior under the documented one-slot/null-cache scope. Final owner storage shutdown must disable new publication before successful reclamation and freeing cold resources.
