# Worker-owned D2H transport source

This private default-off package consumes only `Owner::acquire_features` and `DecodeCapture::acquire` copied staging. The exporter cannot submit a native HC pointer. It never serializes the copied staging/device pointer; full native ownership addresses remain opaque Binding metadata. The owner APIs have already completed their D2D fences before a staging view becomes available.

`owned_transport.{h,cpp}` supplies a single external-worker exporter and explicit HIP resource owner. Enabled worker setup uses the cold-supplied HIP C function table to allocate one pinned host chunk (4–128 rows, at most 3,276,800 feature bytes), one nonblocking stream and one timing-disabled event. No HIP library resolution, initialization, environment arming or automatic resource creation is included. Default-off configuration performs no resource calls. The function signatures/constants were checked against the installed ROCm 7.2 `hip_runtime_api.h` and `driver_types.h` without loading a runtime.

The exporter borrows the complete prefill view while copying bounded chunks, or an exact committed DecodeView. It copies the input IDs into its own bounded byte array, enqueues `hipMemcpy2DAsync` DeviceToHost with row pitch/width 25,600 bytes, records its own event, and performs one event query per `step`. Staging remains borrowed until every enqueued D2H completes. Only then does exact full Binding + ticket + lease generation + capture sequence acknowledgment release Owner's ticket or DecodeCapture's unique FIFO sequence. A busy release retains the copied identity and borrow and retries. A failed enqueue, event record or query retains both staging and pinned host storage; only successful explicit worker stream synchronization permits cancellation acknowledgment. There is no timeout that frees incomplete work.

The worker rechecks lease validity/health before enqueue, serialization and final release. Loss and exact cancellation emit an Abort frame after outstanding D2H completes; explicit `retire(Binding)` also emits a terminal Abort while idle. Sink failure permanently closes the stream, retains any pending borrow until safe acknowledgment, and reports failure. Closing HIP resources requires the exact configured exporter, stopped new work, no outstanding copy and a drained exporter. Owner/DecodeCapture disposal separately requires `disable_new` and their successful `storage_reclaimable` proof. The exporter, staging owner, HIP resource owner, functions and sink must stay alive throughout these debts.

The public `acknowledge` entry point independently checks lease validity/health before recording successful delivery. If the lease becomes invalid after final Data, direct acknowledgment rejects, marks loss and retains the borrow until the worker emits Abort; cancellation acknowledgment can then release safely. The focused pre-fix regression exited 45 and now passes. Already aborted/sink-failed paths preserve safe release, and a busy source release still retains the exact acknowledgment debt.

`worker_io.{h,cpp}` provides a binary file/pipe sink and explicit worker loop. The loop's wait callback, HIP recovery synchronization, file writes and Python/provider processing execute only on that worker. Native callbacks remain the frozen allocation-free/nonblocking Owner/DecodeCapture producers. No exporter entry point belongs in a mandatory gate or ready lookup. Root must supply the worker's scheduling/barrier outside ready lookup and measure that causal path.

Each frame has a 256-byte little-endian header followed by copied signed input IDs and row-major BF16 bytes concatenated in native layer order 4,16,24,36,44. Header fields carry all Binding fields (16-byte session, ticket, lease/cache generations, holder/model/wire/request/birth, slot and total), transport sequence, source, capture sequence, exact mandatory Entry round, anchor/next-current, verified/committed counts, chunk offset/count, shape/order/encoding and header/payload CRC32. Source values are Prefill=0, Verify=1, Scalar=2; Data=1 and Abort=3. A Data final flag completes prefill at exact `Binding.total` or one complete committed DecodeView. Verify transports only the authoritative committed prefix, including its opener, and never its rejected suffix. Scalar transports one real processed row. No provider proposal IDs, native histories or new-current features are fabricated.

`owned_reader.py` reads one bounded owned packet at a time without importing torch, HIP or a provider. Its `OwnedReader` requires a cold-supplied exact Binding, contiguous full prefill from position zero, monotonic exact transport sequence, monotonic capture sequence/round and the expected committed frontier. It rejects foreign/stale metadata, wrong source/count/shape, corrupt/truncated frames and capacity overflow. Abort, malformed transport and unexpected EOF retire the stream. `ProviderReceiver` is an explicit adapter to an already prepared external worker/stamp: it clones owned BF16 host bytes and calls `append_prefill`, `apply_committed_verify` or `apply_scalar` with exact native metadata. It does not create a provider, discover a device, propose automatically or publish a Ready result. The cold provider stamp must use decimal `str(Binding.birth)` as `request_birth` and independently pin the model/tokenizer/drafter identities.

The first query's native current ID/position and each next mandatory Entry round belong to root's separate scheduler/barrier input. FeatureView does not supply a first current ID. After `ProviderReceiver` applies a committed decode view, root may compute the next query only for the exact measured native frontier; it must separately copy the exact Ready result into the retained provider contract. There is no server integration, ready-publication route or demonstrated scheduling window here.

Run `python -B build_qualify.py` for ordinary Windows CPU qualification only. It compiles against the frozen real owner sources, runs lifetime/contention/terminal/copy-failure fixtures, tests HIP function-table behavior with ordinary host stubs, emits a CPU binary wire fixture and checks every BF16 word and all metadata in Python. The Python provider-dispatch fixture uses a fake tensor/worker and does not import or execute a numerical provider. The initial missing-exporter fixture exited 2; the implemented fixtures exit 0. The build writes only inside this folder and records dependency/source/binary hashes in `qualification_receipt.json` and `delivery_seal.json`.

Default CLI invocation (`python -B owned_reader.py`) reports Off. `python -B owned_reader.py --inspect-cpu cpu-wire-fixture.bin` prints only CPU metadata from the synthetic host fixture. The `.exe` fixtures must never be mistaken for a HIP/native runtime test.

Linux compilation/runtime HIP resolution, actual pinned-memory/event behavior, D2H timing, external-provider numerical execution, complete ready/barrier integration, serving correctness, acceptance and throughput remain root-owned and unqualified by this package. No native runtime/ELF execution, WSL use, HIP initialization, accelerator work, API inference, live patch, restart or lifecycle/STATE change was performed.
