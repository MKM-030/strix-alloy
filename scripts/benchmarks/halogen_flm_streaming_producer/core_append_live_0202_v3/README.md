# Corrected Halogen 0.20.2 genuine-v4 NPU source archive

This archive contains the corrected 0.20.2 integration source. It is
**off by default** and is not an installer or a standalone runnable server.
The finite cohort is terminal. Its partial result contains one excluded stock
warmup, zero measured requests and no started NPU helper. NPU rates and speed
changes remain unavailable. See the [terminal report](../../../../docs/benchmarks/halogen0202-real-npu-core-append-20261111.md).

The producer's exact target-engine identity and authoritative-event/report
labels are rebound to 0.20.2. The serial actor, recurrent native arithmetic,
request-scoped backend and unused-head wrapper are unchanged. The manifest
references five byte-identical files in `../core_append_live_v4` instead of
publishing another copy; materialization must place those files beside the new
producer service. The qualified native wrapper is referenced by SHA256 only.
No model, SDK, provider, native binary or credential is included.

The GPU consumer uses the actual 0.20.2 ELF proof. Its cold constructor obtains
the patch, fallback and consume addresses from the same generated pin rows used
for validation. The actual-ELF CPU fixture checks the file hash and executable
signature bytes without loading or executing the engine. The v2 compiler recipe
uses `-mgeneral-regs-only`, `-fno-builtin`, `-fno-stack-protector` and
`-fno-tree-loop-distribute-patterns`. Independent inspection covered all 3,035
callback text bytes and found no SIMD/x87/MMX/opmask dependencies, undefined
symbols or indirect calls. The rejected v1 build retained old constructor RVAs
and omitted this compiler contract; its evidence is preserved separately and
that product must never be loaded.

The RAW layer is tied to four fresh native clock endpoints, nine instruction
windows and the exact C++ clock provider. The existing journal layout and
HTTP-QPC accounting remain intact. Native-T authority wrapping preserves the
new API's generation yields and GEN bytes, including its cached ID serialization.
The upstream rendering and tokenizer defaults are preserved. The small-proposer
seed, prompt prefill, catch-up and READY history remain separate observations;
component milliseconds do not become measured engine token rates.

The finite protocol remains stock / real NPU v4 / stock, each with one excluded
warmup and three measured requests. It uses the same natural 8,192-token request,
128 output tokens, greedy temperature0/seed1, cache off, 32K capacity and paired
8192 prefill settings. Exact native-T/output parity, common RAW instrumentation,
separate native-head/HDO2 counts and ordinary normal-server restoration are
required. A lookup denominator of zero is undefined. Normal startup30/131GiB,
request-entry22/22GiB and continuous18/18GiB reserves remain unchanged.

The source preparation and prior CPU reviews establish implementation scope,
not a live speedup or acceptance result. The terminal offline audit preserves the failed 22-GiB entry wait and the
restored normal server. It establishes no NPU prefill/decode/acceptance result.

The source manifest records exact source hashes and private materialization
paths, unchanged-source references, the copied member list and explicit
exclusions. Runtime profiles, executed bindings, service state, journals and
credentials are deliberately outside that list. Source proof files retain
historical local path references for audit; they are not redistributed payloads.
