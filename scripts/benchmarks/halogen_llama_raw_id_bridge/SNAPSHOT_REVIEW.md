**Verdict: no actionable correctness blocker in the bridge snapshot implementation. Source review permits the proposed finite qualifier; it does not establish state parity, performance or serving readiness.**

- `device_rejection_snapshot` requires an explicit Boolean and defaults false. With false, existing resolution behavior remains intact. The fixed context reference, sequence0, one synchronous owner, pending guard, epoch and saved committed length prevent another save from replacing an eligible round's device slot.
- Save occurs before the first consumed draft. Identical flags3 are used for size/save/restore, and both actual byte counts must match. ON_DEVICE counts only host metadata; it does not report device payload size. The pinned context implementation performs tensor copies before its public operation returns. The extra synchronization is included in command time.
- Restore moves metadata and the original owned committed row into local storage before retirement. It restores recurrence before removing `[old_length, infinity)` from hybrid memory. Restored recurrence is at `old_length-1`, outside that removal range; attention removes the speculative suffix. The public maximum-position check alone cannot prove attention cleanup, so the full-row oracle remains necessary.
- Accepted consumed inputs retain their owned speculative row; remaining authoritative inputs are scalar forwards when the snapshot mode is enabled. Rejected resolution replays every authoritative ID through scalar forwards from the saved boundary. Empty resolution preserves the saved committed row. Publication follows complete replay.
- Retirement, clear, prefill/rebase, eviction and exceptions invalidate snapshot eligibility. Recoverable save failure is recorded and declines restore; recoverable restore/removal/replay failure records a fallback and charges the real rebuild in overall command time. Native assertions/aborts terminate the process and cannot become a successful fallback receipt.
- Clearing metadata does not release llama.cpp's context-owned device snapshot buffers. One reusable sequence slot remains resident until context destruction; this is bounded lifetime, not a per-round release.
