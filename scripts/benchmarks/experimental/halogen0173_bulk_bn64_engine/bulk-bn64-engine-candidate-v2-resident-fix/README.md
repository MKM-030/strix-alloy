# Default-off native BN64 engine candidate v2: resident-query exclusion

This source-only LD_PRELOAD adapter is an isolated experiment for the exact 0.17.3 engine SHA256 `af4f07bbe3759206013eb6f1328095ca2105cfda5127c5b9a2ab93e1aea987b7`. The constructor also verifies the entire embedded 17,765,424-byte native GPU code object at file offset 339968, SHA256 `18937428b544e8a5ef1dae31db97f36136e8cdeca90e6c49458ef831b822a039`. Default behavior forwards original registration and launches unchanged. No host text patch or new device code is used.

The settled source SHA256 is `714b90cf716a0ed2b82deb949394ff4154798a0fadd6c421c39aadd7e3c8c24d`. [host-map.json](host-map.json) records the exact pins, argument layouts, launch shapes, native read bounds and allocation budget. [The independent review receipt](independent-abi-transaction-review.md) documents the bounded ABI, capacity and transaction review. The final one-line portability fix stores `write()`'s result before discarding it, preserving behavior while satisfying GCC's `warn_unused_result` check.

Root-owned build command, from this directory:

```sh
gcc -std=c11 -O2 -Wall -Wextra -Werror -fPIC -shared adapter.c -ldl -lpthread -o libbulk-bn64.so
```

Activation requires both `ALLOY_BULK_BN64_ENABLE=1` and `ALLOY_BULK_BN64_LOG=/absolute/new/exclusive-log-path`; `libcrypto.so.3` supplies host SHA256. Root controls the eventual preload chain and isolated engine lifetime. The log is created exclusively with mode 0600 and is bounded to 1 MiB. No build, engine launch or HIP initialization was performed by this source author. Failed executable/hash or opt-in checks retain stock behavior.

Only the exact normal mode1/outputflag1, N8192/R81920, device0, streamNULL, non-captured launch sequence qualifies. Recognition checks the independently audited 0.17.3 return addresses, descriptors, block/grid shapes, original pointer associations and exact 152-byte native projection prefix. Native `__hipRegisterFunction` calls pass through unchanged; all seven native handles must match their expected descriptor, names and common fat-binary owner before the first remap.

The intercepted pipeline is native items128 → GU128 → DN128split2 → native bulk fold. Replacements are the already registered native items64/GU64/DN64split2 handles. GU/DN grids become 8960/17920; their blocks stay 256. Item generation stays grid1/block512. Fold retains its original handle, grid20480 and all eight arguments. GU/DN aggregates are copied in full with only the item pointer at +0x80 changed. Counts retain the original 8-byte allocation. Packed offset0, scale offsets GU0x32000000/DN0x19000000, strides40/10, codebook[-8..7] and all tensor/metadata bindings remain unchanged.

Separate GU/DN item arrays provide 143360/286720 bytes, each with 4096-byte prefix and suffix guards. Total additional device allocation is 446464 bytes, once per isolated process. Original native arena item buffers are untouched. After stream0 synchronization, raw expert histograms, compact active IDs/prefixes and totalR are read and checked for ascending ownership, complete row sum, nonnegative counts and capacity ≤1792. After items64, native counts must equal the checked 5S64/10S64 and private guards must remain 0xa5 before GU submission. All additional synchronization, copies and checks must count in the engine comparison.

One mutex serializes launch admission; the active transaction binds PID/TID/device/stream. Native launch arguments are copied synchronously. Each attempted GU/DN replacement records its original snapshot and advances the rollback prefix before enqueueing, including launches that return errors. An unmatched continuation, wrong mode/flag/thread/stream/capture or replacement failure replays stock items128 and every attempted GU/DN128 prefix on stream0, synchronizes, disables later remaps and forwards the original call with its original function/grid/block/arguments/shared bytes/stream. Failed replay latches a terminal HIP error for later intercepted launches; the void unregister callback exits127 if replay fails.

Successful original fold submission commits the transaction. Reuse of private arrays is ordered on the same original NULL stream. Graph capture and module launches do not qualify. Registration ownership conflict disables future remaps and triggers rollback before the next intercepted launch. Root may explicitly call `alloy_bulk_bn64_shutdown()` at an idle boundary to restore an active prefix, synchronize and free private allocations. Otherwise bounded buffers live until process exit. The destructor emits only a host summary and closes descriptors; it makes no HIP calls after runtime teardown. Native fat-binary unregister restores any active prefix before unregistering its owner.

Memory safety relies on exact native host ABI bindings and the separately audited native64 read bounds. Packed/scales have exact 865075200/432537600-byte blob bounds with no padding. GU metadata minima are 2560/1280 bytes; DN/fold channel metadata needs 5120 bytes. No device extent query is an admission condition. CPU-safe host argument reads use self `process_vm_readv`, falling back to `/proc/self/mem` if the container blocks the syscall.
