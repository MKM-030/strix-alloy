# Halogen 0.17.3 native bulk BN64 engine experiments

This source-only archive preserves two distinct, default-off experiments for the exact Halogen 0.17.3/gfx1151 engine. The adapter selects already registered native items64/GU64/DN64split2 handles for the bounded N8192/R81920 mode1/outputflag1 route and retains the original fold. It introduces no new GPU code. Enablement requires `ALLOY_BULK_BN64_ENABLE=1` and a new exclusive audit-log path. This archive does not enable the adapter.

V1 completed the frozen engine comparison with output/acceptance parity and comparable clocks, but its audit recorded **zero native64 transactions**. It establishes no BN64 execution or serving gain. [The zero-hit diagnosis](bulk-bn64-engine-comparison-v1/zero-hit-decision.md) explains the source-supported resident-query log collision. Preserve v1 as an unqualified activation attempt.

V2 changes only the constructor to exclude the exact first argument `--resident-gib` before claiming the audit log. The [complete constructor delta](bulk-bn64-engine-candidate-v2-resident-fix/constructor-delta.patch) and [independent source review](bulk-bn64-engine-candidate-v2-resident-fix/independent-resident-skip-review.md) are preserved. Root completed the v2 engine cohort with actual bounded native64 hits. The qualified candidate/before comparison regressed; candidate/after and pooled clocks are incompatible. The adapter remains off. See the [final report](../../../../docs/research/halogen0173-bulk-bn64-engine-20261009.md).

The request is synthetic pseudoprose: 8192 actual input tokens, including 116 repeated input calibration units, followed by 128 ordinary output tokens. Each measured arm has one excluded warmup and three measured requests, with cache/thinking off, temperature0, seed1, MTP depth2 and PLD `3,3`. It is not a natural long-input or NPU result. V2-before reuses exactly the four completed v1-after requests; it sends zero new baseline requests. Shared stock observations must not be counted as additional independent samples across the two experiments.

The 29 authored source, mapping, review, harness and analysis files are copied byte for byte from private `server/.local/optimization9h-20261004/halogen0172-backend-preparation-20261008/`, with original directory names retained. [source-archive-manifest.json](source-archive-manifest.json) records every source/target byte count and SHA256. The [exact activation-bound note](prefill-bulk-moe-retile-scope-20261009/host-route-proof-v1.activation64-exact.md) is included as a sibling source artifact. Binaries, full native disassembly, engine/runtime objects, model data, credentials, profiles/prompts, raw responses, seals and lifecycle receipts are excluded. The final public report retains actual rows and qualification limits without publishing private runtime contents.

These are historical source snapshots and are not runnable at the archive location. The scripts retain private PREP paths and Windows/WSL assumptions. Dependencies outside this archive include the compiled adapter and exact seal/profile/prompt, installed normal 0.17.3 backend and controller/job/memory helpers, migration/owned-handle helpers, Windows PowerShell/PDH, WSL `Ubuntu-24.04`/`revn`, Docker and `aiohttp`. The Linux adapter additionally requires x86-64, native HIP symbols and `libcrypto.so.3`. Links in copied source receipts to excluded evidence identify private provenance. The analyzers use only Python's standard library and separately retained frozen summaries/audits.

Archival copying did not import or execute the scripts, run tests, build, call APIs, change engine lifecycle or mutate Git. Root owns all runtime qualification, final reports and activation decisions. Component gains justify the trial but do not replace full-engine execution, parity and net-rate evidence.
