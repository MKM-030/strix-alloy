## Bounded Reddit lead and a separate draft-cost idea

Two targeted Reddit searches returned a recent [Kyojin release discussion](https://www.reddit.com/r/LocalLLaMA/comments/1wybesy/qwen38flashnext_125b_on_a_single_strix_halo_mini/). Its throughput anecdotes were not used as local evidence. The linked primary repository was inspected at `8c91be29da2cfbaf22ebd89c047ca8eecd4ad28f` (19:50:40 UTC). The [Qwen serving guide](https://github.com/Yamz-Labs/kyojin/blob/8c91be29da2cfbaf22ebd89c047ca8eecd4ad28f/tools/qwen/SERVE.md) describes MTP plus ngram drafting and exact target verification, with different EXL3 weights/runtime.

A source idea distinct from the retired history-lookup proposals is **stopping a sequential draft early using confidence calibrated against tested verifier outcomes**. [DraftConfidenceCalibrator](https://github.com/Yamz-Labs/kyojin/blob/8c91be29da2cfbaf22ebd89c047ca8eecd4ad28f/exllamav3/generator/draft_confidence.py) bins drafter scores, ages accepted/tested counts and retains full windows during burn-in. Its [generator](https://github.com/Yamz-Labs/kyojin/blob/8c91be29da2cfbaf22ebd89c047ca8eecd4ad28f/exllamav3/generator/generator.py) can stop AR/MTP forwards early. This is separate from Qwen's shipped fixed probability-product policy in [spec_policy.py](https://github.com/Yamz-Labs/kyojin/blob/8c91be29da2cfbaf22ebd89c047ca8eecd4ad28f/tools/qwen/spec_policy.py); no calibrated-policy Qwen benchmark was established.

Potential benefit is lower draft/verify work per committed token, affecting Decode. Prefill is unchanged. The acceptance fraction could rise merely because fewer positions are attempted; it must be accompanied by accepted/attempted counts, elapsed time and committed-token counts. It is a source-only idea, **not an actionable Halogen runtime route today**: the current public contract exports neither per-depth native confidence nor a supported stopping hook. An argmax-only proposer cannot train this score mapping. Do not reopen the automatically rejected native audit to obtain either. A future owned-proposer evaluation requires already supported score export, target verification and correction/rollback ownership, then a complete matched engine comparison. NPU involvement provides no inherent advantage.
