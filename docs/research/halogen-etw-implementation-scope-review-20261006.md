## What the implementation can close

The historical PID4 sample, `2.628345930526%` at `2026-10-06T10:07:29.2052859Z`, cannot be recovered by a new recorder. Its original PDH timestamp/integration interval and packet/allocation provenance were not retained. The rejection remains valid. A prospective capture can answer ownership for a **new** counter interval only if that capture resolves the complete relevant graph. It cannot retroactively validate the rejected window or qualify the partial `+1.185202%` prefill / `+2.168056%` decode deltas.

System paging has its own contexts and DMA buffers and performs transfer, fill and page-table work affecting other processes. Therefore a packet executing in System's context needs allocation-beneficiary provenance; the context's process owner does not establish Halogen origin. [Microsoft system paging process](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/system-paging-process)

The narrowest useful supported implementation is one native x64 program with separate `collect` and offline `decode` modes, plus disk receipts. It records evidence, materializes exact schemas and values, and constructs only supported, lifetime-scoped relations. It must not encode the disputed pointer aliases as facts. A full resolver becomes possible only after documented/provider-source semantics or captured explicit bridge records establish the unresolved relations below. Repeated equal numbers or nearby timestamps alone do not do that.

## Concrete first increment

**Recorder.** Use `StartTraceW`, `EnableTraceEx2` and `ControlTraceW` for one uniquely named, directly owned DxgKrnl file session. Enable only the reviewed provider selection, without stacks or general CPU sampling. Record requested properties, actual adjusted properties, API statuses, session identity, capture boundaries and final loss counters. Stop only the owned session. Access failure is a technical result; this design supplies no privilege or token workaround.

Request sequential logging, `MaximumFileSize=64` in ETW megabytes, 64 KiB buffers and minimum=maximum=64: a requested 4 MiB pool. ETW may adjust the buffer size/counts; query and retain actual values, `EventsLost` and `LogBuffersLost`. The file cap is a disk limit. A cap hit, early end, or nonzero loss makes coverage incomplete. [ETW properties](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_properties)

`EVENT_TRACE_NO_PER_PROCESSOR_BUFFERING` makes that starting pool independent of the processor-count minimum, but Microsoft advises against it at high volume, for example above 1,000 events/s. Its rate/loss suitability is unmeasured here. If per-processor buffering is needed, compute and observe the actual CPU-dependent pool within the retained memory budget; do not silently expand it. Sequential mode stops at its file limit; circular overwrite would destroy earlier lifetime evidence. [Logging modes](https://learn.microsoft.com/en-us/windows/win32/etw/logging-mode-constants)

`Base | References | Resource | LongHaul = 0x845` remains a candidate keyword mask, not a coverage proof. Preserve a complete installed descriptor/schema/map receipt for the selected events. Guest identity, GPUVA or hardware queue coverage may require other reviewed keywords. Avoid PID filtering that removes System operations or owner/lifecycle records. `EnableTraceEx2(EVENT_CONTROL_CODE_CAPTURE_STATE)` can request provider state; it neither guarantees that DxgKrnl emits all needed rundown nor establishes when that rundown is complete. Retain emitted records and verify relevant coverage. [Provider enable/state API](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-enabletraceex2)

Use QPC (`Wnode.ClientContext=1`) and retain frequency and bracketed QPC/Windows UTC calibration. QPC time does not follow wall-clock adjustments. [ETW clock selection](https://learn.microsoft.com/en-us/windows/win32/etw/wnode-header) A new sampler must preserve original PDH interval boundaries/raw timestamps, engine instance and request boundaries; a Windows timestamp written after querying the counter remains inadequate.

**Offline materializer.** Use `OpenTraceW` / `ProcessTrace` with `PROCESS_TRACE_MODE_EVENT_RECORD | PROCESS_TRACE_MODE_RAW_TIMESTAMP` and `EventRecordCallback`. Persist ETL header clock information and raw event QPC, complete descriptor, provider, header PID/TID, flags, raw payload reference and decode status. Offline file consumption and retention of original timestamps are supported. The unused `EVENT_TRACE_LOGFILEW.EventsLost` member is not a loss receipt; retain controller statistics. [ETW consumer structure](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_logfilew)

Use TDH per exact schema, with a bounded metadata/map cache. Preserve field names, types, numeric values and optional map labels. Determine pointer width from event-header flags; unresolved width stays unresolved. Respect schema count/length properties, nested structures and payload bounds. For `43/v0`, materialize `uiNbAllocations`, pointer `Allocations[]` and Boolean `Write[]` together, without inventing their object namespace. TDH supports metadata, enum-map lookup and counted properties; those facilities do not establish ownership or handle equivalence. [Microsoft incremental TDH example](https://learn.microsoft.com/en-us/windows/win32/etw/using-tdhformatproperty-to-consume-event-data)

Stream normalized records to disk; encode 64-bit handles/identifiers losslessly, without floating-point conversion. Bound application allocations and metadata growth, mark oversized/failed/unknown decodes unresolved, and use bounded passes or disk indexes for lifetimes. Do not load or map the whole ETL. Controller/decoder private-commit targets of 16/32 MiB, in separate phases, are plausible native implementation targets, **not measured guarantees**. TDH/native overhead, ETW adjustment and file cache prevent claiming a hard total physical-memory bound below 0.1 GiB; keep the existing reserve checks and observe process/system memory independently.

**Relation report.** Preserve handle namespaces as separate typed objects. Candidate same-field chains are `Context.hDevice → Device.hDevice`, `Device.DxgProcess → Process.DxgProcess`, `Process.DxgVirtualMachine → VM.DxgVirtualMachine`, and `HwQueue.hContext → Context.hContext`. They require captured scope and lifetimes and do not themselves resolve System allocation beneficiaries. Emit each unresolved edge and source record references; never label a merely decoded event as an attributed packet.

## Go/no-go criteria for root

**Go now:** implement the bounded collector, schema/map receipt, incremental typed decoder and explicit unresolved-edge report. Review and offline fixture verification can be completed without claiming attribution. These components are reusable evidence infrastructure and may reveal whether a complete supported route exists on the installed provider.

**No-go now:** implement hard-coded allocation/DMA/sequence aliases, claim an exclusive Halogen resolver is already supported, reinterpret the historical veto, or report acceleration progress from collecting/decoding evidence. No available evidence makes that claim reviewable.

**Prospective closure:** for the new counter interval, require a complete loss-free relevant packet/engine execution graph and allocation provenance to a uniquely identified Halogen task, with valid lifetimes and clock mapping. Zero reported loss is necessary but insufficient: disabled keywords, missing rundown, unknown schemas and unresolved owners still leave gaps. If a narrower documented ownership path eliminates an edge above, use it; do not demand redundant event families. Otherwise report `unresolved` and retain the historical rejection. This is an evidence condition, not a request for renewed user permission.
