# Native I4R fallback decision for exact Halogen 0.17.2

**Completed result:** the native `HALOGEN_I4R_LAST=0` comparison established no qualified serving gain. The candidate remains disabled and will not be repeated unchanged. See the [measured comparison](C:/Projects/strix-alloy-clean/docs/benchmarks/halogen0172-native-i4r-fallback-20261008.md).

The source rationale below records the premeasurement recommendation: one normal-profile cohort with **`HALOGEN_I4R_LAST=0` only**, leaving `HALOGEN_FLASH_MOE_V2` and the other compute settings at the frozen stock values. It was a resource-pressure and synchronization hypothesis for the repeatedly observed routed small-row operation, without an established throughput improvement or weight-traffic reduction. No custom kernel, host patch, weight conversion, or launch omission was proposed.

## Identity and scope

The retained engine is 26,178,504 bytes, SHA256 `ac73b1df48510a34e0246a77bd984f1df0e02e5fa6cf1530d3d77c91d3c0e913`, from image digest `sha256:0c83ef1093520f0d5b5a00285e59e7ac6b85b1922917fc4a3df95ac5a2638cdd`. The selected embedded gfx1151 code object is 17,765,424 bytes, SHA256 `18937428b544e8a5ef1dae31db97f36136e8cdeca90e6c49458ef831b822a039`.

All work in this directory is CPU-only extraction, metadata parsing, byte checking, and disassembly. The ELF and embedded device objects were never loaded or executed. No hardware, HIP execution, build, installation, lifecycle action, or root-state edit was performed. `host-eligibility.md` and its bounded host excerpts explain the source path; `native-pipeline-binding-metadata.json` joins exact registration bytes, descriptor addresses, name strings, embedded symbols, argument metadata, ISA captures, and hashes.

The diagnostic census contains 2,688 consecutive route/GL/FL triples per captured request at returns `0x17d5cc6`, `0x17d3d39`, and `0x17d3e59`. Their descriptors are `0x18f43a8`, `0x18f42f8`, and `0x18f4300`. The observed GL template<1> is selected by actual `N>2`. A particular `N=3` is plausible under depth-two verification but **not recorded by this census**. Its host intervals do not measure GPU execution or delineate genuine prefill/decode phases.

## Exact switch and native reachability

`HALOGEN_I4R_LAST` is the string at `0x18af5`; cache `0x18fc0b0` and guard `0x18fc0b8` are shared by both inline initializers. The helper-local cold initializer starts at `0x17d3526`, loads the environment name at `0x17d3544`, and calls `getenv` at `0x17d354b`. Absence returns `AL=1` at `0x17d35b9`. A present value is disabled exactly when its **first byte is ASCII `0`**, compared at `0x17d3555`; this is not numeric or whole-string parsing. Use the exact string `0`. The outer initializer starts at `0x17e0b1b`, references the same name, cache, and guard, and returns to the outer dispatch.

For the existing typed routed-int4 helper `0x17d0080(model, layer_index, N)`, the flag comparison is `0x17d16d6`. Setting zero takes `0x17d16e2 -> 0x17d1713` into a complete existing fallback. It does not enter the separate V2 comparison at `0x17d0b68`. The operation remains in the original typed helper and uses its native gate/up and down tensors, half-input representation, route indices, route weights, metadata, scratch allocator, and output pointers. The four following compute stages preserve the native argument values and dispatch geometry:

| Native stage | Descriptor / launch return | Grid x, for positive N | Block | Native arguments |
| --- | --- | --- | --- | --- |
| `k_i4r_rows<2560>` gate/up | `0x18f4350` / `0x17d183f` | `200*N` | 256 | byte weight pointer; long `0x32000000`; int `1280`; half input; int `10`; route indices; float scratch |
| `k_i4r_gu_epi` activation/repack | `0x18f4358` / `0x17d192c` | `ceil(50*N/8)` | 256 | float scratch; int `10*N`; two native half metadata pointers; half intermediate |
| `k_i4r_rows<640>` down | `0x18f4360` / `0x17d1a3b` | `400*N` | 256 | byte weight pointer; long `0x19000000`; int `2560`; half intermediate; int `1`; route indices; float scratch |
| `k_i4r_fold` final weighted output | `0x18f42e8` / `0x17d1b6c` | `ceil(20*N/8)` | 256 | float scratch; int N; float route weights; native half metadata; ushort input; float input; ushort output |

All blocks are `(256,1,1)`, grids have y/z one, dynamic shared-memory bytes are zero, and stream is zero. Static LDS requirements below are additional to the zero dynamic value. There is no new `N>=3` rejection in this fallback. This establishes source eligibility for the observed branch; it is not a universal proof for arbitrary N, different model geometry, or runtime pointer extents.

The native ABI is independently pinned by embedded metadata. Both `k_i4r_rows` variants have 56-byte kernargs: pointers at offsets 0/24/40/48, an eight-byte by-value long at 8, and four-byte integers at 16/32. `k_i4r_gu_epi` has 40-byte kernargs: pointers at 0/16/24/32 and a four-byte integer at 8. `k_i4r_fold` has 56-byte kernargs: pointers at 0/16/24/32/40/48 and a four-byte integer at 8. The stock GL ABI remains a distinct 176-byte layout with an 88-byte by-value I4rSd at offset 72, its integer at 160, and final pointer at 168; it must not be repurposed as the native 56-byte layout. The stock FL layout is 96 bytes. No argument substitution is involved in the environment switch.

The same shared flag also changes outer routing. At `0x17d5934`, zero branches `0x17d593b -> 0x17d618d`, bypassing the stock `k_route_topk_w_grp<2>` descriptor. If cached global `0x18fa528` is nonzero, native descriptor `0x18f43b8` (`k_route_topk_w`) uses grid `ceil(N/8)` and block 256. Otherwise `0x18f43c0` (`k_route_topk`) uses grid N and block 512. Both use launch return `0x17d63cc`, zero dynamic shared memory, stream zero, and the existing score/index/weight globals. This is the full native setting, including its routing change; the stock grouping/preparation arrays must not be assumed to retain the same producer. Exact registrations and embedded metadata for both routing variants are in `native-pipeline-binding-metadata.json`.

The fallback entry calls preparation helper `0x17d3650` before the four direct stages. It returns immediately when model byte `+0x10` is clear. When that byte is one, it clears the byte, requires N in 1..8 plus nonnull layer fields `+0x640/+0x648/+0x650`, width `+0x65c==2560`, and qword `+0x660==640`; invalid gates print a message and exit. Layer `+0x658==3` selects helper `0x1829980`, otherwise `0x182aeb0`. Both use CPU grid helper `0x17c86d0`. The bounded N=3/4 terminal paths add exactly one native shared preparation launch from descriptor family `0x18f4de0/0x18f4de8/0x18f4df0/0x18f4df8` or `0x18f4ee0/0x18f4ee8/0x18f4ef0/0x18f4ef8`, with grid `(20,T,1)`, block 256, zero dynamic shared memory, and stream zero. Exact terminal identities for N=1/2 and N=5..8 are outside the saved stub excerpts. This is compute, with no device-copy call in the bounded N=3/4 paths. It cannot be treated as host-only or omitted from a full launch count. The same split parameter T adds `20*T` to the stock GL grid, giving `200*N + 20*T` when optional model/SD work is supplied, otherwise `200*N`; stock FL grid is `400*N`. The switch therefore splits that optional work into an additional native submission. Source analysis alone does not provide the runtime model flag, T, or optional-stage selection.

The preceding scratch reservations are shared by enabled and disabled paths. With `r12d=10*N` and `r13=50*N`, the first reservation is `r13<<8 = 12,800*N` bytes and the second is `r13<<11 = 102,400*N` bytes. Both end offsets are checked against existing global capacity at `0x17d166e/0x17d169e`, before the flag comparison; the scratch base and pointer lifetime are the native ones. These formulas are source bounds for the current small-row shape, not argument snapshots or runtime capacity evidence. The gate/up float result uses the second region, activation writes the first, down reuses the second, and fold reads it. No increased allocation requirement is introduced by changing this flag.

## Why this could change GPU performance

Both native projection kernels perform packed-int4 decoding, load half activations through LDS, and accumulate with `v_dot2acc_f32_f16` and its dual form. The native gate/up and down templates are fixed to the existing reduction widths 2560 and 640. Their output is FP32 scratch, followed by the native activation/repack or final fold. The activation uses native float exponential/division work, metadata, lane permutations, and `v_fma_mixlo_f16`/`v_fma_mixhi_f16` before writing the half intermediate. The final fold retains its route-weight combination, metadata, residual input, and explicit high-16-bit rounding sequence. These are existing arithmetic implementations; static analysis does not promise bitwise equality to the fused implementation.

| Kernel | Code bytes | VGPR / SGPR | Fixed LDS bytes | Private scratch / spills |
| --- | ---: | ---: | ---: | --- |
| Stock observed `k_i4r_rows_gl_o<1>` | 27,652 | 110 / 52 | 10,248 | 0 / 0 |
| Native `k_i4r_rows<2560>` | 16,016 | 99 / 18 | 5,120 | 0 / 0 |
| Stock observed `k_i4r_rows_fl_o` | 6,860 | 96 / 31 | 1,284 | 0 / 0 |
| Native `k_i4r_rows<640>` | 4,332 | 96 / 17 | 1,280 | 0 / 0 |
| Native `k_i4r_gu_epi` | 2,564 | 40 / 13 | 0 | 0 / 0 |
| Native `k_i4r_fold` | 2,088 | 53 / 14 | 0 | 0 / 0 |

Every listed kernel uses wave32 and permits at most 256 work-items per group. The gate/up resource reduction is concrete: 11 fewer VGPRs, 34 fewer SGPRs, and approximately half the fixed LDS per group. This may improve residency or scheduling at small N, but no occupancy threshold or residency gain has been established. The native projections each contain one static `s_barrier` instruction and no global atomic instruction. The stock GL/FL code contains ten/three static barrier sites and two/one global atomic-add sites, plus optional integrated-down/counter branches controlled by its wider argument state. Selecting the native projections removes those branches and atomic sites from those launched kernels. **Static site counts are not executed instruction counts**, and the trace does not establish which optional stock sites ran.

The routing alternatives also differ concretely: stock grouped routing uses 98 VGPRs, 45 SGPRs, and 1024 bytes LDS; native `k_route_topk_w` uses 68 VGPRs and zero LDS, while the alternate `k_route_topk` uses 57 VGPRs and 6184 bytes LDS. The former native branch provides another resource-pressure hypothesis; the latter trades lower register use for more LDS and a 512-work-item block. The cached route selector's runtime value was not captured, so do not assign the candidate to either routing variant based only on its environment delta.

The countervailing cost is explicit: the helper uses four direct compute stages instead of the observed GL/FL pair, adding activation/repack and fold submissions. Together with one selected routing launch, that is five direct launches versus the stock observed triple; eligible optional preparation on the bounded N=3/4 path makes the native count six while stock integrates that work into its GL grid. FP32 gate/up output is materialized and read by activation; FP32 down output is materialized and read by fold. The half intermediate is also stored and read. With the current shape, the native staging sizes are 51,200*N gate/up float bytes, 12,800*N half-intermediate bytes, and 102,400*N down float bytes; each is written then read by the next stage. This is 332,800*N bytes of explicit inter-stage scratch traffic before common metadata/output traffic. It is **not an exact net increment over stock**: stock has its own intermediate and conditional scratch traffic. There is no proof of less weight traffic, shared expert-weight reuse across N, fewer quantized dot products, or a throughput win. The justified hypothesis is lower projection resource/control pressure overcoming the extra stages and scratch traffic.

## Why V2=2 is excluded from this cohort

The getter at `0x17d3610` defaults to one; only parsed integer two selects two. Its cache is `0x18fa460`. That selector changes separately observed bulk `q4moe` implementations while preserving their host aggregate and launch geometry. It neither controls the observed small-row GL template nor changes the fallback above. Specifically, observed bulk gate/up descriptor `0x18f6a80` maps from `q4moe::k_q4moe<1,0,128,Tune<0,128>,1>` to `0x18f6ab0`, the corresponding leading-template-two kernel. Down descriptor `0x18f6a88` maps from `<1,2,128,Tune<0,128>,2>` to `0x18f6ab8`, the leading-template-two kernel. Those baseline descriptors occur 48 times each per captured request.

For that actual BN128 pair, V2 mode-two gate/up has 256/72 VGPR/SGPR versus mode-one 252/60, with the same 36,864 bytes LDS; down has 254/65 versus 255/52, again with the same LDS. Their code sizes and ISA differ, but no present-binary comparison against 0.16.2 exists and no static advantage sufficient to combine them has been proved. The old 0.16.2 V2 result is not a measurement of this pinned 0.17.2 fallback. `HALOGEN_FLASH_MOE_FUSED_N` and bulk V2_MINN are also not established selectors of the repeated small-row pair.

The files formerly called `native-v2-2-*` were renamed to `gl-row2-*`, and `capture_native_variant.py` to `capture_gl_row2.py`. They describe `k_i4r_rows_gl_o<2>`, selected by actual `N<=2`, **not** `HALOGEN_FLASH_MOE_V2=2`. They are retained only as a bounded alternative inventory; no GL-row selector patch is proposed.

## Cohort and bounded dispatch receipt

The parent owns lifecycle, measurement, historical screening, exact-output/acceptance checks, and stock restoration. The proposed delta is the single environment value `HALOGEN_I4R_LAST=0` on the same pinned engine and frozen normal profile. Record the actual child-process environment and binary/image identity in the normal lifecycle manifest. This proves the configuration submitted to the getter; it does not independently prove the observed GPU branch or runtime dimensions.

If a bounded launch receipt is already available during qualification, bind its process/module identity to this engine and count the four candidate `(return, descriptor)` pairs above, with grid/block/stream and launch status. Confirm disappearance of the specific stock GL/FL pair at the same operation boundaries. Count routing and any preparation separately because the shared setting can also alter outer preparation selection. A descriptor match alone is insufficient: these native kernels have other call sites. The fallback return addresses distinguish this exact operation. The gate/up and down grid counts recover N without dumping weights or large argument buffers. Keep this receipt separate from clean throughput measurements. No new capture is required merely to restate the static gate.

Runtime qualification must still establish successful serving, output/acceptance behavior, and actual performance on the frozen request cohort. A gain must be measured, repeated against stock, and assessed with both prefill and decode behavior; CPU launch intervals are not GPU timing. If the candidate is slower, resource pressure did not outweigh its added launches/traffic for this workload. If runtime dispatch is not collected, report performance as a result of the recorded native setting and avoid claiming an independently observed kernel selection.

The recommendation authorizes a reversible native-setting trial only. This directory contains no performance result and no artifact for custom execution.
