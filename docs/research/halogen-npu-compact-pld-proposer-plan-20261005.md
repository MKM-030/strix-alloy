# Compact NPU token proposer for the private PLD seam — 5 October 2026

**Prioritize Qwen3.5-0.8B as one real, token-only autoregressive proposer, using the prepared FastFlowLM NPU2 package.** This is a bounded source-only candidate plan, not a working feed or a speed result. Complete the offline proposal adapter and qualify its hit/no-hit scope before model acquisition or hardware work. The necessary weights, complete token-map proof and raw-ID accepted-prefix transaction adapter are currently missing.

Installed FLM 1.0.7 and the Qwen3.5 runtime DLLs satisfy the version/family declarations; execution compatibility has not been tested. ## Token compatibility is a gate

The real target tokenizer is retained at `C:\AI\models\halogen-flashnext\tokenizer`. Its `tokenizer.json` is 12,809,320 bytes, SHA-256 **`0997f410c57a1f4e53b09e4be8f4a172d90edd9564368fb0847030937229b9f3`**. Parsed metadata contains 248,044 base entries, 247,587 merges and 33 added tokens at IDs 248044–248076. EOT/im_start/im_end IDs 248044/248045/248046 agree with Qwen3.5 metadata. The FLM package tokenizer is 12,807,982 bytes, SHA-256 **`5f9e4d4901a92b997e463c1f46055088b6cca5ca61a6522d1b9f64c4bb81cb42`**, matching the official Qwen3.5 tokenizer pointer.

Matching head dimension and these special IDs are encouraging, but the files differ and the full map is unproved. Before feeding any ID, compare every base and added token's ID/bytes, merges, normalizer, pre-tokenizer, decoder and special-token rules against the pinned package revision. Account for model IDs beyond tokenizer-defined entries. Prefer exact shared-ID compatibility; a lossy decode/re-encode bridge changes proposal identity and context. Decline this candidate if a faithful bridge would require retraining or material latency. Consume authoritative committed IDs directly, without adding FLM chat templates, think tokens or tool masks.

## Private seam and bounded state contract

The [static insertion audit](halogen-npu-native-pld-injection-scope-20261005.md) identifies RVA **`0x172e95f`**, after native copying of context IDs and before constraint handling and native first-head equality. It is **PLD-hit-only**: native lookup remains, and no-hit rounds cannot receive this feed without a separately qualified insertion. Keep the native opening gate, target verifier, accepted-prefix handling, replay, grammar and stop/EOS behavior. An independent first-token mismatch takes the stock MTP/scalar fallback; do not manufacture that token from future target predictions. Start without a constraint object and cap the reply at `min(stock_n, 3, native_allowance)`. All invalid, stale, late or unavailable replies retain the untouched stock block/count.

Own the proposer state separately from Halogen. Bind every reply to an explicit request-initialization nonce, committed token position, committed-prefix fingerprint, context-window origin and one-shot round identity. Native object pointers and counts do not establish freshness. Reset, replacement, cancellation and failed initialization must retire the nonce and outstanding replies. The native audit supplies birth/destructor anchors but does not yet prove all reset/cancel synchronization or a live shim.

Maintain a bounded window of **512 committed tokens initially**, with 1,024/2,048 only as acceptance-versus-cost alternatives. These are design limits, not qualified FLM context settings. Prefill once per window or rebuild, then predict at most three IDs from available committed context. After native verification, synchronize to the actual accepted prefix plus target correction/bonus. Discard every rejected draft suffix. A shifted rolling window changes recurrent/attention state and requires a correctly bounded rebuild unless the runtime proves an equivalent operation; dropping IDs from host history is insufficient.

Local FLM source provides a concrete raw-ID direction: `src/include/causal_lm.hpp:25–65` declares `forward(int)`, `prefill(vector<int>&)`, `clear_context()`, `checkpoint()` and `restore()`. `src/common/AutoModel/automodel.cpp:184–199` compares the entire cached history and clears context on divergence. `src/common/AutoModel/modeling_qwen3_5vl.cpp:294–308` restores a prompt checkpoint and its saved history. The engine implementation of arbitrary accepted-prefix restore was not located or qualified. These source declarations neither establish the installed DLL ABI nor provide a ready commit/discard service. A private raw-ID adapter must qualify checkpoint state, history, sampling and logits together; until then, clear and rebuild from committed IDs is the explicit correctness fallback. HTTP full-prompt replay is not a draft transaction.

The selected language payload is about 535 MiB on disk; the manifest's declared footprint is 1.3, not a measured residency result. At 2,048 tokens, configuration-derived bf16 K/V storage for the six full-attention layers alone is about 24 MiB, before recurrent state, convolution history, checkpoint copies, logits, activations and runtime allocation. This makes a bounded candidate plausible enough to prioritize, but neither proves the allocator honors the requested bound nor permits omitting rebuild/prefill cost. Optional vision weights are outside this token-only design; whether the prepared loader can avoid them still needs qualification.

## Acceptance and benefit gates

First qualify an offline finite CPU packet adapter with clearly labeled fixtures; that proves protocol behavior only. Then, with a genuine independently predicted block, record native-hit coverage, first-head gate pass rate, exact accepted-prefix lengths 0–3, stale/late replies, fallback rate and all initialization/rebuild costs. A hit-only feed can improve an existing PLD suffix, but cannot claim the coverage of a no-hit drafter. Quantization, context truncation, model size and target/drafter distribution differences may make exact acceptance too low even when text looks reasonable.

Use held-out target prefixes split by complete documents/requests, with no saved answers, future verification rows or prompt-copy leakage as proposer inputs. Compare to the unchanged native PLD/MTP policy on the same requests. Any later distillation should teach the target's next IDs from available prefixes and be justified by held-out accepted-prefix improvement; text quality or perplexity alone is insufficient. Pin the training/evaluation/tokenizer/package revisions. A trained quantized artifact would need a new export and qualification, not inherit this prepared checkpoint's receipt.

The required result is lower elapsed time per **actually committed token** on matched work. Include proposal generation, transport, packet checks, retained native lookup/opening-head work, target verification/commit/replay, rejection fallback, window rebuilds and shared-memory/scheduling contention. Count missed readiness and startup over actual requests. The existing small-model throughput is not a break-even estimate, and another disconnected FLM benchmark would not qualify this plan.

**Next authorized scope remains static/offline preparation:** finish the proposal adapter's hit/no-hit contract, enumerate the exact missing artifact and raw-ID transaction requirements, and preserve stock fallback. Model acquisition, live state probing, shim installation and any hardware cohort require a concrete candidate prediction path plus a plausible end-to-end benefit case. This note used existing metadata/source reads and prior official-source evidence only; it made no code changes, downloads, model loads, hardware/build/test or lifecycle actions.
