# Bounded acceptance/speed decision — 0.17.2

2026-10-08. **Completed result:** native `HALOGEN_DRAFT_VOCAB=0` reduced Decode by about 6.03% against the linked stock baseline and combined acceptance by 1.95 percentage points. The candidate remains disabled and will not be repeated unchanged. See the [measured comparison and clock qualification](C:/Projects/strix-alloy-clean/docs/benchmarks/halogen0172-native-full-vocab-20261008.md).

The binding below retains the premeasurement rationale for one bounded comparison, with Q8 and I4R overrides omitted and fixed MTP2 otherwise unchanged. It establishes original HT4 projection, existing target-head reuse, and no candidate-created full-head allocation; it did not predict acceptance or speed. The source review used retained reports and CPU-only disassembly of inert ELF data, without hardware or lifecycle work. Later measurement results are recorded separately above.

## Why this differs from completed work

Stock 0.17.2 already enables reduced vocabulary, adaptive language/code group selection and Q4 draft-row repacking. English projects48,082 rows; the full head has248,320 rows. Simply enabling draft vocabulary is already the default. Q8 changes representation precision and memory traffic while retaining the same pooled/group ID sets. Its completed arm regressed descriptively by5.48% in decode and1.95 percentage points in combined acceptance; the after bookend is missing. Repeating Q8 is not recommended.

The control changes both candidate coverage and projection representation: a correct next token excluded from the selected group cannot be proposed by that group regardless of Q4/Q8 precision; the original HT4 path also bypasses reduced Q4 repacking. A wider candidate set can change the winning wrong ID too; acceptance improvement is **not monotonic or guaranteed**. Whether any verified token on the frozen synthetic pseudoprose cohort is omitted from the selected group is unknown. A measured gain would not by itself distinguish shortlist recovery from numerical/kernel differences.

At the time of the source review, no executed 0.17.2 full-vocabulary arm appeared in the reviewed fixed2/adaptive/Q8 reports. Older0.16.2 full-head results change the engine version and do not supply this single-variable result. Native adaptive2..3 was already2.85% slower than its fixed2 bookend mean at the same combined acceptance; that negative is not reopened. The retained depth1 evidence also warns that a higher accepted fraction can accompany lower speed.

The actual native loader reads store/variant at `0x180bf5e`, sends store16 to `0x180c11b`, stores the original payload in descriptor `+0x30` at `0x180c128`, and computes source bits `(variant>>1)&0x7f` at `0x180c12c..0x180c131`: this checkpoint maps to **4-bit original HT**, not an 8-bit source. Exact loader bytes are `180c12c: d1 e8`, `180c12e: 83 e0 7f`, `180c131: 41 89 46 48`.

The MTP fallback's `0x17e48f0` first calls the original-HT helper `0x1814dc0` at `0x17e4925`. For one query, `0x1814efa` calls `0x18266f0`; its type4 branch at `0x1826722` goes to `0x1826970`. This consumes original packed uint32 weights and FP16 HT scale data. The matching retained bundle0 device range is RVA `0x524600`,8,664 bytes.

Stock reduced Q4 instead dequantizes original HT4 into **uint16/BF16** block staging via `0x17f2e50`, then runs `k_dv_quant` and the reduced Q4 helper `0x17f4750`. BF16 rounding is visible at retained bundle0 device `0x4a9894/0x4a98b8` (`+0x7fff`, retained-bit tie adjustment, high-half stores); draft Q4 also converts its scale to FP16 at `0x21c930`. This corrects the earlier generic uint16/FP16 staging description. Exact `0` bypasses those added staging/requantization stages; original HT4 quantization and native floating-point rounding remain. Numerical equivalence or acceptance improvement is not established.

Original `lm_head.weight` is resolved at `0x1787937` and its descriptor copied into model `+0x5e0..+0x650` at `0x178793c..0x17879ab`. Model setup calls this head setup at `0x17835db`, **before** reduced setup at `0x17835f4`. This is existing model initialization required by the target head. The inspected one-query HT route uses preallocated globals and lazy policy/getenv initialization; it has no new GPU allocation for `DRAFT_VOCAB=0`.

## Cost and useful outcome

The full projection does substantially more vocabulary work. The5.16-fold English row-count ratio is **not** a timing multiplier: native original HT4/reduced Q4 kernels differ. Skipped setup allocations do not prove decode improvement.

For unchanged greedy output, compare total time per actually committed token. In a simplified continuing two-draft round, useful commits are `k=1+P(first match)+P(first two match)`. If extra full-head cost is `d` on a stock round taking `r`, a necessary local screen is `delta_k > k*d/r`. Native verifier/replay, changed round boundaries, misses, stops and initialization belong in the complete request comparison. Combined accepted/drafted counts alone cannot evaluate that inequality.

Root has prepared the non-run full-vocabulary wrapper with `DRAFT_VOCAB=0` as the sole added environment value and Q8/I4R overrides absent. Root may explicitly link the prior I4R stock-after four requests as this new arm's baseline; this is reuse of a measured baseline, not a fresh independent baseline. Candidate acceptance must be measured rather than fixed to stock70/113, with exact verified-output parity and total decode/request wall retained, followed by stock-after. No additional head diagnostic, inventory expansion or repeat baseline is needed for this bounded source decision.
