# PLD authoritative-outcome handoff and early ready scheduling

**A concrete causal overlap path exists, but useful next-round readiness is not established source-only.** After the PLD accepted-prefix call at `0x172d80a` returns, an owned copy of at most four authoritative output IDs can start private drafter resolution. The normal, MTP-enabled continuation then performs output handling and accepted-prefix head replay before the next lookup. A later seal must prove that the complete output block became the request's actual committed prefix. Neither a measured commit-to-no-hit window nor a qualified native capture/transport implementation exists. Do not run a snapshot hardware qualifier or a new engine cohort now.

The [offline no-hit consumer](../../scripts/benchmarks/halogen_pld_nohit/README.md) has removed one source-contract gap: it can validate an already-owned packet and return the stock continuation or the bounded proposal join. **A live native consumer remains absent.** Its synthetic CPU checks do not supply `CallerTruth`, epoch ownership, authoritative outcomes, transport, or actual machine-state preservation. One bounded preview/seal outcome component connected to that consumer is justified as the next source implementation. This report adds no implementation or serving-gain claim.

## Actual commit and continuation

All addresses are RVAs in the pinned retained ELF, not supported exported callbacks. The PLD route is inside decoder FDE `0x171c260..0x17305ed`.

| Native path | Established data/control flow |
|---|---|
| `0x172d5d3..0x172d618` | Copies `[current, proposals...]` into outer `RSP+0x980`, records verifier input count, and calls `0x17dcfc0`. |
| `0x172d630..0x172d650`, mismatch `0x172d7bf`, zero-match `0x172dabf` | Compares the proposal with completed target predictions. Let `a` be matched proposals; `k=a+1`. `R15=a`, outer `[RSP+0x40]=k`; zero match explicitly selects `k=1`. |
| `0x172d7da..0x172d802` | Copies the `a` matched IDs into outer `RSP+0x1980` and writes the target correction/bonus at index `a`. Outer `RSP+0x30` also retains this final ID. This is the shifted output block, not the verifier's `[current,...]` input block. |
| `0x172d803..0x172d80a` | `RDI=model`, `ESI=k`; calls accepted-prefix helper `0x17def00`. It advances target position from `P` to `P+k` and handles rejected target state. |
| Return `0x172d80f` | `RBP=request`, original outer RSP and the output block remain available. The first instruction is exactly five bytes, `f3 0f 6f 45 40` (`movdqu xmm0,[rbp+0x40]`). A post-return observer could copy `k` IDs before caller scratch is reused. This is a candidate observation site, not a qualified five-byte detour. |
| `0x172d890..0x172d8eb` | Iterates the output block. Each token is appended to the request PLD vector by `0x1759550` at `0x172d8c8`, then passed to output/stop helper `0x173b430` at `0x172d8dc`. A nonzero helper result branches to `0x172d943`; it can truncate the emitted/vector prefix and bypass ordinary replay. |
| `0x172d8ed..0x172d8f7` | Reached only after all `k` output callbacks returned zero. Loads the final correction from outer `RSP+0x30` and stores it at `request+0x15c`. A seal after that store can check actual vector length/tail and current token. The instruction at `0x172d8f7` is six bytes, `8b 85 dc 01 00 00` (`mov eax,[rbp+0x1dc]`). Its installation is also unqualified. |
| `0x172d8ff → 0x172db6f → 0x172e037 → 0x172e058` | On the normal continuation (`request+0x1dc<=0`, `model+0x900` and `+0x901` enabled, no constraint object), calls `0x17dcc90(model, outer RSP+0x1980, k)`. |
| `0x17dcc90..0x17dcd68` | Checks replay eligibility/count, restores/tag-invalidates native carry when appropriate, copies the last accepted residual snapshot, calls full head `0x17db310` at `0x17dcd4f` with count `k` and position `current_position-k`, and caches its returned opening proposal. The output token block is already known before this head work. |
| `0x172e05d → 0x172e12d/0x172e818 → 0x172d95b` | Updates native adaptation/statistics and returns through decoder cleanup. Normal surviving iterations reach `0x171c5f0`; scheduling/model-slot selection precedes later decode setup at `0x172c21d..0x172d251`. Next-round allowance/request setup is `0x172d25a..0x172d32f`; lookup/no-hit handling follows. There is no direct `commit → no-hit` jump. |

The normal path therefore supplies a **structural** window containing accepted head replay and host work. Replay is conditional. A positive `request+0x1dc` takes `0x172d934` and skips this replay; MTP flags can decline it; output stop/error can exit first. Other queued requests or scheduler delay may lengthen a particular interval, but neither is a guaranteed budget for the selected request.

Capturing before `0x172d80a` would require provisional target-commit semantics. The smaller design starts only after it returns. Even then, distinguish target acceptance from successful completion of the whole native output loop. Using the full output block to prepare privately is causal; admitting its next-prefix packet before that loop succeeds is unsafe.

## Every native outcome must advance the feed

Packet selection and outcome tracking are different events. Disabled/unready/malformed/stale no-hit packets, absent proposals, native opening mismatch, and ordinary stock rounds still produce authoritative outputs. A stateful drafter cannot wait for its next successful custom selection to learn them.

| Outcome route in the bounded greedy scope | Required handoff |
|---|---|
| PLD target verification, including `a=0` | Preview from the postcommit block above; seal only after full native output-loop success. A zero-match PLD block still produces one correction. |
| No proposal or opening mismatch at `0x172d425`/`0x172dd8d` | Both reach stock fallback through `0x172d42b`. When the native bounded controller is eligible, call `0x173b630` at `0x172db61` owns the actual outcome. The failed custom block owns none of those IDs. |
| Native controller `0x173b630` | At `0x173b741..0x173b759`, controller-frame `RSP+0x30` holds its matched drafts plus correction; `R15=k`. Commit is `0x173b764`; post-return is `0x173b769`, with `RBX=request`. Output-loop append/callback sites are `0x173b825`/`0x173b838`. After the full loop and zero callback result, `0x173b884..0x173b88c` enters the continuing path; current token has been stored at `0x173b84e`. Seal there only with actual vector/current-token equality. Ordinary replay is `0x173bb5e`; suppression at `0x173bb2c..0x173bb50` skips it. Controller offsets use its own frame, never the outer decoder RSP. |
| Scalar/count-one stock routes | Target forwarding is `0x172d4ad` or `0x172d6dd`; selection is `0x172d4e1` or `0x172d711`. The selected ID is stored at `request+0x15c`, and optional constraint validation completes before `0x172d515` or `0x172d745`. These are possible one-ID previews. PLD append is `0x172d53d` or `0x172d76d`; output callback is `0x172d579` or `0x172d7b5`. A postcallback zero result, one exact native-vector append, current-token equality and unchanged owner are required for a continuing seal. These routes supply no guaranteed postseal accepted-head-replay window. |
| Stop/error, cancellation, replacement, reset, unsupported path | Revoke the reserved next round and every associated ready packet. Do not seal the full preview when only a prefix was emitted. Preserve native processing; retire private work. An unexplained vector/current-token change or missing outcome disables the feed until an explicitly qualified reinitialization. |

The finite first implementation must handle the listed stock routes even if it elects to retire a drafter on unsupported suppression/reset paths. Positive PLD policy and absent sampler keep the PLD vector appends visible in the intended scope. It must not infer canonical history from aggregate acceptance counters, response text, speculative head calls, or target rows that were not selected as this native outcome. Initialization/batched-prefill output paths such as append `0x172cc97` are outside the active handoff interval: take an exact new seed after that phase, or retire and reinitialize on reentry rather than silently miss their changes.

## Concrete owned interfaces and sequence

The following are proposed component interfaces, not existing callbacks:

```text
OwnerSeed { birth_nonce, native_context_epoch, model_binding, tokenizer_binding,
            prefix_length, target_position, current_id, window_origin,
            owned_window_ids[<=512], full_prefix_fingerprint }
RoundBinding { birth_nonce, native_context_epoch, round_id, previous_frontier,
               prefix_length, target_position, current_id, window_origin,
               prefix_fingerprint }
OutcomePreview { round_binding, source_route, outcome_sequence,
                 matched_native_count, target_position_after,
                 count[1..4], owned_output_ids[4], reserved_next_round_id }
OutcomeSeal { same outcome_sequence, exact next_binding, Continue | Retire }
PreparedPacket { immutable authenticated existing HGNPLDP1 frame,
                 trusted native_context_epoch, next_binding, slot_generation }
```

Native context epoch is distinct from the llama bridge's internal epoch, which can advance during normal resolution. Never substitute one for the other. Existing wire version 1 has no epoch field; its association with the authenticated frame needs a trusted envelope. The current consumer already checks that envelope against `CallerTruth.context_epoch`.

1. **Seed and owner:** assign a new nonce after successful native construction, never from the address or frontend request ID. Privately copy the exact canonical native PLD IDs and current token at a qualified postinitialization boundary. The constructor's vector/current-token append is an anchor, not proof that it is the correct later serving seed. Record actual target position independently of vector length. Validate the seeded tail/current-token relationship; do not reconstruct a missing prompt ID from the retained shifted-head trace. A finite growing256-to512 proposer uses the exact last256 IDs with a declared origin; it is a distinct context policy. Keep a bounded owned native suffix and incremental canonical-prefix fingerprint; epoch/reset qualification remains necessary even when the digest matches.
2. **Round start:** the native owner reserves a successor round ID at a sealed frontier, so the producer can bind a packet before lookup. At actual decoder setup (`0x172d2a9..0x172d32f`) adopt that reservation only if request birth/epoch, model/slot, target position, vector extent, owned suffix and current token still match. Unexpected interposed changes revoke it. The consumer's RBP/original outer RSP truth comes from the actual saved native frame, independently of the packet. Full-prefix fingerprint collision assumptions must be explicit; validate exact copied window IDs too.
3. **Immediate postcommit preview:** copy the bounded output block and primitive identities into a preallocated owned event slot. Publish it by release-store only after the complete copy. No native pointer, model pointer, outer/controller stack pointer or native-vector view leaves the callback. Do not allocate, wait, lock, perform device work, or call serving from an interior observer. A separate transport owner may acquire/drain immutable events. Ring exhaustion revokes feed eligibility; it cannot overwrite an unread event and conceal a missing prefix update.
4. **Early private work:** the external worker may restore/prune/replay these already-selected outputs and prepare a successor proposal while native output/replay continues. Its result remains ineligible until the matching continuing seal exists. A terminal or mismatching seal retires this private advancement; no tentative packet can mutate native state. Only one context/snapshot slot and one speculative proposal are pending. All proposal IDs are recorded before a later outcome enters resolution.
5. **Native seal:** after complete output success, check the actual vector grew by exactly `k`, compare its new tail with the owned block, check final current ID and target position, and preserve birth/epoch. Advance canonical length/fingerprint/window and publish the exact successor binding. A nonzero callback result or unknown reset publishes retirement, not a full continuing seal. Destruction/replacement/cancellation invalidate registry and packet generations before native release. Worker completion never dereferences the native owner; an old completion simply fails its generation check.
6. **Producer resolution:** resolve every native round, including rounds that consumed no custom packet. Native `a` describes whichever native proposal was verified; it cannot be passed as an acceptance count for an unused external proposal. Match recorded external IDs against owned authoritative outputs. Retain speculative inputs only under the previously documented exact-prefix/opening-reuse/no-eviction rules; otherwise restore the before-proposal snapshot, prune attention, and replay every authoritative ID scalarly. Conservatively restore an unused/opening-rejected proposal rather than invent custom acceptance. Count1 consumes no speculative model input and still forwards the native output. An idle drafter with no pending proposal appends all outcomes scalarly. The main checkout bridge's `commit(accepted,extra)` does not implement this general complete-outcome operation; use the actual complete-resolution design, not a fabricated accepted prefix.
7. **Ready publication and consumption:** both a successful private preparation and its exact seal are required. Authenticate/encode outside the native consumer, then publish a stable generation with release/acquire ownership and no ABA reuse. At `0x172d3bd`, the existing fixed-storage consumer checks current binding and actual B. A late result declines immediately; never wait or silently rebind it to a newer prefix. A packet generated with count3 may fail a smaller next-round B; do not truncate it. Successful consumption uses the existing join `0x172e95f` and records the birth/epoch/round once.

Keep one fixed64-round ledger and a finite event budget with at most four IDs per outcome. Queue later sealed outcomes in order if private resolution is still busy. Expire the missed round's reply eligibility at its seam, but retain the owned outcomes needed to synchronize private state. A worker may propose only for the latest sealed eligible frontier; it cannot publish an old packet after catching up. Budget exhaustion, a gap, reset or producer error disables the feed and retains stock execution. This is a default-off finite feed; an always-running producer has not been implemented or qualified.

## Opening eligibility and readiness cost

No-hit success retains the native opening machinery. At `0x172d3d8..0x172d425`, positive native MTP policy/no suppression/position conditions select the comparison with cached `request+0x160`; an absent cached ID takes native head work through `0x172dd36`, with comparison at `0x172dd8d`. Mismatch falls to stock fallback. Independent proposal generation never receives or copies the native opening ID. The retained positions also have native branches which skip this comparison; a first feed must separately require the documented gate-eligible scope rather than claim every bounded packet necessarily executes equality. Actual frame truth must establish those conditions at consumption. The retained workload's 12/15 target-next/native-opening equality is offline reference evidence, not live gate rate or no-hit eligibility.

Define `W = next actual no-hit arrival - postcommit preview publication` for the same continuing birth/epoch, and let `C` include preview dispatch/cross-WSL transport, old-round resolution, next snapshot, two speculative scalar forwards for count3, owned-logit selection, encode/authentication/return transport and ready publication. A timely packet requires all work plus seal arrival to precede that specific seam. Capture/seal/validation and retained native work also enter complete serving cost. Missing readiness cannot be converted into an assumed overlap credit.

The retained raw head trace contains no commit/no-hit timestamps. The historical count1 head bracket, **3.32356 ms** averaged across 73 instrumented calls, is neither `W` nor the latency of count `k` replay at this PLD site; non-count1 calls were excluded. It cannot establish the needed overlap. The measured growing GPU proposer averaged **10.148 ms** for a three-ID proposal alone and **22.202 ms** for complete resolution, before this transport. Its six append resolutions averaged 4.717 ms and nine rebuilds 33.859 ms. Those are historical component costs with another state path, not timings for a new snapshot implementation or a joint schedule. No source-derived instruction count, device bandwidth estimate, idle scheduler assumption, or subtraction of these different cohorts supplies a useful readiness prediction.

The [snapshot audit](halogen-recurrent-snapshot-adapter-feasibility-20261006.md) pins a 19.265625-MiB recurrent slot and **36 separately submitted blocking Vulkan tensor copies per save and per restore**, plus context synchronization. Their latency is unmeasured. Their contention with native accepted-head replay must be charged; overlapping two GPU clients does not make those costs disappear. Initial seed, missed packets, resolution after every stock round, final round and any fallback/rebase belong in total cost per actually committed target token.

| Placement | Decision for this path |
|---|---|
| CPU | Fits fixed-storage native capture, ledger and packet validation. A CPU model still pays host/DDR contention; the retained 45.09-ms proposal-plus-one-append proxy already fails the optimistic screen. No CPU rerun follows from this schedule. |
| GPU/Vulkan | Best retained proposer cost and a matched recurrent restore API; the plausible connected candidate. Native replay and snapshot/drafter work share GPU/DDR/queues. Neither useful readiness nor gain is established. Remain off. |
| NPU/FLM | Same owned token/outcome protocol can describe it, but Vulkan snapshot proof does not transfer. XRT padded-attention rollback and caller ABI remain unresolved; prior 67.68-ms proxy fails. NPU local memory is not exposed target GPU capacity. No NPU run is justified. |

## Remaining native proof and one next implementation

The decisive unknown is **whether complete causal resolution and next preparation, including real cross-process publication and target contention, can finish before a qualified next no-hit seam**. Static flow gives possible native work to overlap; it does not establish a useful schedule. Before any hardware qualifier, the implementation must also provide actual owner/reset truth and installed capture paths. Existing same-instruction-stream cancellation narrows one race only; workers, indirect callbacks, in-place context/model-slot reset and asynchronous exceptional release are not fully excluded.

The new interior preview/seal sites need full GPR/RFLAGS/extended-state preservation, original-frame addressing, proper SysV alignment/red-zone treatment, replay of displaced instructions, unwind/signal handling, computed-entry exclusion, image/ASLR pins and atomic installation/removal. `FXSAVE` and the synthetic 1024-byte opaque frame do not qualify enabled XSAVE components, size or alignment. The existing no-hit test does not prove these new sites. Live installation remains unqualified. The user's standing measurement and lifecycle authorization remains valid; these are implementation prerequisites, not a request for another approval.

**Next step: implement one default-off fixed-storage `native_outcome_handoff` source component alongside the existing no-hit consumer.** It should own seed/frontier/round reservations, the bounded preview/seal/retire event ledger, exact stock-outcome advancement, and the adapter that constructs `CallerTruth`/trusted packet eligibility only from a sealed current frontier. Its explicit caller ABI must distinguish outer PLD, nested controller and scalar frame layouts above. Native adapters must supply independently qualified copied facts; a fixture flag cannot substitute for a real reset map. Include finite source-level fixtures for missing/duplicate/out-of-order seals, partial stop, unused/opening-rejected proposals, stock/count1 advancement, cancellation/address reuse and late publication. Verify that no packet becomes eligible from preview alone and that every incomplete/unknown transition leaves stock no-hit replay available. This component must call the same existing consumer interface, not create a second standalone predictor protocol.

That single source implementation makes the acceptance/state handoff concrete and reviewable. It adds no model runtime, transport launcher or installed detour; those remain subsequent implementation boundaries. Do not run a disconnected recurrent timer while caller truth and authoritative handoff remain absent. If native capture/reset ownership later qualifies, a single finite connected qualifier must record actual preview/seal/seam/ready times, real gate/late counts, exact scalar incremental-state parity and complete target time per committed token. Source proof alone does not request that run now.
