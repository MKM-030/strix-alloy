# CPU code lookup prototype

Purpose: return inspectable source locations for locate-only tasks without automatically asking the main model. This is a task-time experiment; it establishes no direct native prefill/decode gain. Root owns the frozen held-out questions, semantic model staging, and any later hardware qualification.

The production corpus is exactly Git-tracked Python files under server/ and backends/halogen-wsl2-0.17.3/scripts/ in C:/Projects/strix-alloy-clean. Filter the tracked inventory before reading: exclude .local, hidden/cache/private-data components and credential/private file names; refuse symlinks, junctions, nonregular files, and resolved paths outside the repository. No home scan, recursive source discovery, untracked input, package install, or source execution occurs.

Use Python standard library only. Build a single deterministic JSON generation from sorted relative paths, complete-file SHA256 values, bounded consecutive line chunks, identifier sets and lexical term counts. Chunks contain at most32 full lines and8192 UTF-8 bytes; oversized single lines are explicitly omitted. A chunk ID hashes version, path, file hash and exact one-based inclusive span. The generation hashes the complete canonical index body. Publish it with one adjacent temporary file and atomic replace; metadata and postings cannot diverge.

Query checks the approved repository and generation hash, then verifies the same tracked-file inventory and every indexed file SHA256. Changed, missing or newly selected source returns stale_index with no excerpts and rebuild_required. Exact whole-query identifier or path matches lead the ranking; otherwise standard BM25 (k1=1.2, b=0.75) selects at most12 positive-score chunks with stable deterministic ties. Return at most3 re-read exact spans, each bound to complete-file hash, chunk ID and index generation. No positive lexical match yields no_match. Multiple exact locations or a top-score tie yields ambiguous rather than an answer-confidence claim.

The API has a default-off reranker protocol over the same frozen shortlist/excerpts. Enabling later requires explicit caller opt-in and graph/tokenizer/preprocessing SHA256 identity. GPU-busy state or provider failure keeps an explicitly tagged CPU result. There is no provider runtime import, graph, session, network call or main-model callback in this implementation. Reranker scores mean rank only; they do not establish sufficiency or correctness.

CLI: build and query, with explicit --repo and index confined to this isolated work directory. API: build_index, load_index and lookup. Test fixtures live in this work directory and mock only Git inventory/approved-root discovery so their real filesystem can be exercised without Git mutation. Meaningful cases cover exact spans, ambiguity/no-match, stale file refusal, and provider default-off. A real corpus build/query is a CPU smoke probe, not held-out evaluation. No server/API/lifecycle/GPU/NPU action or Git mutation is authorized here.
