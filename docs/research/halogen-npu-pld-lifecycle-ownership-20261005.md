# Native PLD lifecycle and synchronous consumer ownership — 5 October 2026

**The retained native control flow supplies concrete request birth, replacement, cancellation and destruction boundaries for a synchronous finite ready-packet consumer at the PLD seam.** The native command-handler cancellation path and the reviewed PLD path execute inside the same connection-handler function. A consumer that finishes locally, never waits and never re-enters serving cannot be interrupted by another command on that instruction stream. This narrows the ownership problem substantially. It does not establish exclusive ownership against every worker, indirect callback, exception or in-place reset, and does not qualify a detour for installation.

The intended scope is a token-only consumer at RVA `0x172e95f`, with a producer owning a private copy of its context. The producer retains no native request, context-vector, model, stack, constraint or device pointer. A missing, stale, malformed or unsuitable packet leaves the stock proposal and native control flow intact. The first native-head gate, target verification, accepted-prefix commit and replay remain native as established in [the insertion-scope receipt](halogen-npu-native-pld-injection-scope-20261005.md). That receipt is unchanged.

## Ownership map

The request allocation is `0x1f8` bytes. The model pointer is request `+0xd8`, current token `+0x15c`, cached native opening proposal `+0x160`, and PLD subobject begins at `+0x170`. Its vector begin/end/capacity are `+0x178/+0x180/+0x188`; hash state follows. The vector can reallocate during append, so a retained context pointer is unsafe even before destruction.

## What same-instruction-stream cancellation proves

The reviewed accept branch calls `accept` at `0x171b9c8`, invokes `0x171c260` directly at `0x171ba1a`, then closes the connection at `0x171ba21`. It does not spawn that particular handler call. Inside the same containing FDE, command iteration reaches the length switch at `0x171c9c2..0x171c9de`, compares the command with retained string `X` at `0x171c9e5..0x171c9f1`, parses its ID at `0x171ca15`, searches queued holders at `0x171ca32..0x171ca85`, then checks the lone holder at `0x171ca87..0x171caa0`.

Consequently, that command-handler cancellation cannot run simultaneously on this same native call stack while a normal synchronous detour at `0x172e95f` is executing. A consumer that reads an already-ready local packet, validates it and returns immediately needs no asynchronous native-pointer cancellation scheme for this command path. Calling native output/serving routines, waiting for a producer, yielding through serving, or starting nested decoding would invalidate this argument.

There are worker/thread facilities elsewhere in the binary. Retained import mapping includes `pthread_mutex_lock`/`unlock` (`0x18d3280/0x18d3290`), thread start (`0x18d3630`), join (`0x18d3660`) and condition wait (`0x18d3980`); a worker thread start occurs at `0x173eac3`. Their existence neither proves nor disproves concurrent mutation of this request. This audit has not proved that worker/model references cannot reach the request or its context, nor excluded asynchronous signal/exception destruction. Global thread exclusivity must not be inferred from the direct accept branch.

## Minimal owned-packet contract

1. A producer is given a privately owned copied prefix/current token, a fresh birth nonce and context revision, request/model/tokenizer identity, native position and bounded proposal cap. No native or device address crosses the boundary.
2. Its reply contains finite token IDs and those identities. Packet publication is completed before a release-store marks it ready; the consumer acquires readiness and reads a stable owned packet. Sequence/slot reuse must prevent ABA. The exact packet representation and atomic/lifetime scheme remain implementation work.
3. The synchronous consumer verifies the entire envelope and all IDs into private bounded scratch before changing any native byte. It validates the birth/revision, position, context length and exact copied prefix/current token; a digest alone is not exact identity unless the protocol explicitly accepts its collision model. It checks tokenizer/model identity, finite length, integer/vocabulary bounds and the native allowance.
4. Initial scope declines nonnull constraint object (`request+0x1e8`), malformed/stale/absent packets, unknown owner/reset state and any count exceeding `min(stock_n, 3, native_allowance)`. It neither enlarges native buffers nor broadens the seam to no-hit rounds.
5. Only after successful validation does it publish proposal IDs at original stack `+0x360` and deliberately update the saved native count register. It preserves the native first-head gate; mismatched opening tokens still enter the existing native MTP/scalar fallback. Native target verification, accepted-prefix commit, output stop and replay own the result.
6. Destruction/replacement invalidates registry ownership before release; producer cancellation may simply abandon privately owned work. Old completed replies can never become a packet for a later birth. In-place reset must advance private context revision through a proved boundary, or consumption remains disabled for that state.

This contract permits finite offline CPU adapter work without asserting that a trained compatible predictor, NPU execution, runtime callback or speed improvement exists. A live producer must never be on the consumer's critical path when no valid packet is ready. Even a correct token packet yields no useful acceptance if the native opening proposal disagrees.

## Interior-detour preservation contract

At `0x172e95f`, RBP is the request, RBX is the positive stock proposal count and original RSP is the stable outer-frame base. The proposal array is at original RSP `+0x360`. This is an interior block, so ordinary function-entry caller/callee-save assumptions do not apply.

The first displaced instruction occupies `[0x172e95f,0x172e966)` and is exactly `48 8d 85 e8 01 00 00` (`lea rax,[rbp+0x1e8]`). A reviewed detour using that seven-byte interval must replay this instruction and resume at `0x172e966`. The containing five-instruction block ends at `0x172e97b`; its SHA-256 is `3e95f9f01d988fb7353cc764ab0c899ae21196ac545c54593eb342423d1fdf83`. Encoded direct incoming edges land at the seam, not its interior; computed-target exclusion remains unproved.

The shim must preserve all general-purpose registers, original RSP/RBP, RFLAGS and complete live floating/vector state, plus every native local. Only the proposal bytes and explicitly saved RBX/count may change on successful consumption. Native offsets must always be computed from the original outer RSP; helper pushes must not silently retarget them. Preserve proper SysV stack alignment and conservatively protect the 128-byte area below original RSP before helper calls. No allocation, blocking lock, wait, native reentry, device operation or exception may cross the consumer boundary.

`FXSAVE` alone cannot preserve live upper YMM/extended state. A complete save/restore policy must account for enabled XSAVE components and alignment/size; this audit did not query hardware or implement such a policy. Unwind/signal treatment, relocatable trampoline placement, atomic installation/removal, image identity/ASLR validation and instruction-cache/permission mechanics are also unqualified. Instructions later overwriting RAX/RDI/flags do not prove every other register or vector lane dead. A normal C helper call without a proved full preservation shim is unsafe.

## Decision and bounded next proof

**Proceed with a finite, CPU-only owned packet adapter and static shim design; do not install a live native detour yet.** The reviewed lifecycle is concrete enough to avoid imposing a general asynchronous native-pointer design on a synchronous consumer. It is not sufficient to claim universally safe live installation.

The smallest remaining native proof is: enumerate in-place request/context reset and ownership transfer paths; connect the worker entry/reference graph to request/context accesses or exclude them for the selected serial serving mode; qualify complete machine-state/unwind preservation at the interior seam; and demonstrate registry invalidation plus packet slot lifetime without native-pointer publication. Only then can a bounded live lifecycle test be proposed. Existing stock behavior remains the fallback until those proofs and the separately authorized runtime validation exist.
