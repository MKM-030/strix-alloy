## Optional Omni and vision

`voice/optional-omni/omni_protocol.py` implements a transport-neutral text-session protocol with fake-socket tests. It is not wired to Native or startup. It serializes turns, binds application request IDs to server turn/generation IDs, accepts only matching terminal metrics and full text at `response.text.done`, ignores old-generation output, suppresses output after cancellation and closes failed sockets. Context patches append exactly once and never imply a second user turn. No durable resume, model selection, business cancellation, credential enforcement or spoken-delivery acknowledgment is claimed.

Handshake and active-turn waits use absolute deadlines. Control sends (including cancel, context update, playback and close) have a one-second bound; context's bound also covers waiting for the turn lock. Failed-socket cleanup has its own 250ms bound by default. A transport which does not finish closing cannot retain the caller or turn lock indefinitely. Cancellation propagates after bounded cleanup, and the session is marked unusable before that cleanup starts. A transport task that ignores cancellation may continue internally, but it is detached from the failed session and cannot authorize another turn; the caller is never made to await that task without a deadline.

The reference WebSocket service has no HTTP chat/health or authorization. The standalone manifest lists its PCM16 16 kHz input/`input.commit` and framed 24 kHz output contracts; parsing helpers are present, but no live audio path is enabled. `playback.state` is stored by the reference service and does not establish text heard or authorize actions. Text mode still loads the entire Omni checkpoint. Historical protocol/audio evidence is not present-day ServiceNow or Gemma-coexistence qualification.

`vision-assets.catalog.json` records previously observed local asset/shard presence and the required authenticated attachment path. It does not assert current hash, inference or video readiness. Matching base weights/projectors, attachment validation/privacy, authoritative task binding and measured runtime/memory evidence are still needed. Omni, vision, authority and full-mode capabilities remain false. Audio endpointing, Silero/noise behavior and managed TURN policy are unchanged.
