# Halogen 0.15.1: w4b versus v2 at 262144 capacity

Measured on the same 128 GiB Ryzen AI Max+ 395 / Radeon 8060S Windows/WSL2 host.
The Windows graphics carve remains 64 GiB and WSL ceiling 56GB. Neither driver,
BIOS nor clock configuration was changed. The v2 adaptation preserves a contiguous
device allocation while uploading in 64 MiB staging pieces; device memory can use
Windows shared backing and is not synonymous with dedicated VRAM.

## Matched cold-prefill / decode results

Each core point has one warmup followed by three measured repetitions. Inputs are
exactly 512 or 2048 tokens including chat template; decode emits exactly 128 tokens.
One slot, temperature 0, thinking off, cache off. Cold means no prompt-prefix/KV
reuse; model/OS caches were not globally evicted between repetitions. Token counts and zero cached input
are checked. Serial and MTP output hashes match within each checkpoint; different
checkpoints are not required to give identical text. Capacity is not occupied depth.

The table uses **derived clock-calibrated phase rates**, tokens/second, mean +/-
sample standard deviation. The latter is repeat variation, not a confidence interval
or the full calibration uncertainty. WSL's monotonic/raw clock ratio varied; every
request retains its own measurement and Windows QPC cross-check. A within-request
clock-rate change can leave residual phase uncertainty. These are not GPU speedups.

| Weights | Input | Prefill-only | Serial prose TG128 | MTP prose TG128 | MTP repetitive TG128 |
|---|---:|---:|---:|---:|---:|
| w4b | 512 | 967.74 +/- 9.57 | 34.50 +/- 0.24 | 42.41 +/- 0.13 | 77.53 +/- 0.50 |
| w4b | 2048 | 1323.38 +/- 9.06 | 34.08 +/- 0.19 | 42.39 +/- 0.10 | 75.58 +/- 0.12 |
| v2 | 512 | 1025.14 +/- 7.08 | 36.96 +/- 0.28 | 43.17 +/- 0.20 | 83.10 +/- 1.33 |
| v2 | 2048 | 1358.56 +/- 1.02 | 36.17 +/- 0.27 | 45.27 +/- 0.20 | 80.71 +/- 1.36 |

Repetitive copying is unusually predictable and is not the ordinary-chat score. The new weights and memory placement differ: w4b uses the copy48/host-registered profile, while v2 uses contiguous device allocation with bounded staging. This is not an isolated kernel or quantization A/B.

These are Windows counters, not total model physical RAM. GPU/shared CPU counters
must not be added as independent pools. Start admission is 46 GiB physical for w4b,
36 GiB for v2; both retain the 12 GiB physical/commit runtime reserve and a separate
125 GiB commit-headroom requirement at this capacity. Different starting desktop
and page-cache states limit direct memory attribution solely to weight compression.

## Managed gateway experiment

The first managed integration attempt refused a source snapshot that changed after
launch, before model loading. Another attempt found that a whole-file checksum read
retained too much WSL page cache and crossed the 12 GiB reserve before allocation.
Both failures were retained. The verifier now uses bounded reads/range cache advice;
the subsequent managed run stayed above 40 GiB free and stopped with memory recovery.

The first proxy put a full engine-health probe before each request. The paired test
found roughly 0.7-1.0 seconds extra wall time. Readiness now runs independently with
a bounded freshness lease; failed readiness or upstream errors invalidate it.

| Mode | Direct mean | Gateway mean | Mean added wall time |
|---|---:|---:|---:|
| serial | 5.0585 s | 5.0594 s | 0.87 ms |
| mtp | 4.3881 s | 4.4088 s | 20.77 ms |

Three paired measured runs per mode after warmup; small positive/negative differences include normal run noise. Outputs remained identical and real SSE ended with [DONE]. This does not prove zero overhead under all load.
