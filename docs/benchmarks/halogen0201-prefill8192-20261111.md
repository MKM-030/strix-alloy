## Result and current serving configuration

Prefill improves at both input sizes under the declared input-matched
protocol. The 8K candidate exceeds the before control by 26.22% and the after
control by 17.95%. The 16K candidate exceeds them by 4.58% and 13.17%.
The selected prefill setting is the only change between arms, applied to both
`prefill_chunk` and `max_prefill_tokens`. [Prospective V2 plan](halogen0201-prefill8192-plan-20261111-v2.json).

Both candidate output hashes differ from their 2048 controls. This leaves
causal decode comparisons unqualified, with `decode_comparison_qualified=false`
and empty decode-delta fields. The table records the observed rates and API
acceptance for each generated trajectory. The 2048 before and after controls
restore their exact output hashes and counters. Stock-control drift also
persists. RAW lower and upper bounds describe timestamp bracketing, and
statistical confidence intervals were not estimated.

The normal online server uses paired 2048 while further work targets a
configuration combining higher prefill and decode. The measured 8192 setting
is selectable through the existing Windows PowerShell 5.1 launcher after a
normal controlled stop.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Halogen-ServiceNow.ps1 -Profile CurrentText32K -Slots 1 -KvPoolPositions 32768 -Concurrency 1 -PrefillTokens 8192 -ConsoleTrace
```
