# Halogen 0.18.16: independently captured PP1 Prefill

The serial **8,192-input / 1-output** cohort measured **1,906.29 Prefill tok/s** using independent CLOCK_MONOTONIC_RAW endpoints. Native endpoints measured 1,906.29 tok/s on the same intervals. One warmup is excluded; three measurements remain: 1,827.48, 1,859.96 and 2,031.42 RAW tok/s.

All four requests match the earlier plain OEM Performance PP1 requests in exact request bytes, output, token counts, finish reason and zero-draft accounting. Each retained 8,248-byte journal contains two bound Prefill endpoints; all four request IDs differ. API native durations agree with the captured native endpoints. Both native duration and the conservative RAW upper duration fit inside each request's complete Windows QPC HTTP interval, including the excluded warmup.

This is an independent phase measurement, **not a new optimization or a clean HTTP speed gain**. The observer records bookkeeping and flushes a journal after Prefill; complete HTTP includes that work. No time scaling or overhead subtraction is applied, and duration enclosure does not establish exact cross-clock alignment or explain any clock discrepancy.

The result is **0.98% below** the historical standalone PP1 mean of 1,925.16 tok/s. That reference used a different engine, context/workspace and operating environment; this is numerical proximity, not a matched reproduction using the same protocol. The new capture does not invalidate the historical reference's retained calibration.

This report supersedes the earlier pending PP1 qualification. The earlier plain PP1 native observation of 1,613.36 remains unqualified: its native Prefill durations exceed their enclosing HTTP durations on all four saved requests. Those values are retained unchanged. The new capture does not rescale or repair them or establish the cause.

The normal visible 0.18.16 server was restored with the original source hashes and observer binding/DSO removed.
