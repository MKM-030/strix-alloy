# Halogen 0.15.0: PP/TG and allocated-context comparison

Measured 29 September 2026 on the existing Windows/WSL2 Strix Halo host.
This is a benchmark record, not a new runtime release or a v2-checkpoint test.

## Configuration and interpretation

Ryzen AI Max+ 395 / Radeon 8060S, 128 GB unified memory; Windows host with
64 GiB graphics carve and WSL memory ceiling 56 GB. Halogen 0.15.0 uses the
existing w4b checkpoint plus overlay. One session; prompt cache off; prefill
chunk and max-tok arena 2048. BIOS, drivers, clock settings and memory policy were not
changed. Package power was not measured or matched to the reference machine.

Allocated capacity is NOT occupied context. Each combined test processes
exactly 2048 fresh input tokens (including chat template), then generates
exactly 128 tokens. A larger capacity only reserves a larger context/KV budget
in this sweep. No 32K/128K/256K filled-prefix depth curve was measured.
Three measured repetitions follow warmup; tables show mean +/- sample standard deviation, not a confidence interval. Serial/MTP request order alternates.
The same calibrated prompt bytes are reused across capacities; cached tokens
are verified zero. Greedy output hashes match between serial and MTP and across
repetitions. Prose and predictable repetition are separate workloads.

## Clock calibration: do not silently compare incompatible seconds

WSL CLOCK_MONOTONIC advanced about 1.100000 times CLOCK_MONOTONIC_RAW.
A separate two-message interval check measured 10.010665 s monotonic,
9.100610 s raw, 9.100826 s Windows QPC and 9.100604 s Windows UTC.
The API's raw engine fields are retained. Calibrated rates below are DERIVED:
reported engine rate multiplied by the independently measured monotonic/raw
ratio for that request. Raw intervals matched Windows QPC; every retained
request checks this. No clock setting, engine timer or runtime source was patched.

During the later 126K run the clock ratio changed again. Each request therefore
uses its own measured ratio, never a blanket +10% multiplier. Calibration
measures the request-bracketing clock interval, not the GPU's internal phase
boundaries; within-request clock adjustments can leave residual phase-rate
uncertainty. These are derived, approximate comparable rates, not a speedup.
Original fields and Windows whole-request times remain in the JSON.

## External reference numbers, not new local measurements

| Reference workload | PP tok/s | Serial TG tok/s | MTP mixed TG tok/s | MTP repetitive TG tok/s |
|---|---:|---:|---:|---:|
| Gufo, d0 approximately pp2048/tg128 | 1628.52 AR / 1602.82 MTP | 25.87 | 32.20 | 59.30 |
| llama.cpp controls in the same Gufo report | 489.59 AR / 468.76 MTP | 22.20 | 31.73 | 48.12 |

The Gufo report uses Unsloth UD-Q4_K_XL plus a shared Q8_0 draft sidecar on
native Strix Halo, not these HGN weights or this WSL hybrid. Its table was
measured September 22-27, mostly one warmed sample per point. Its configured
capacity is 133760; its depth rows are OCCUPIED cached prefix lengths, not
just allocation sizes. The synthetic generator and task instructions are
reused here, but exact token calibration/padding means the prompt bytes are
not claimed identical to the external run. These are contextual references,
not a controlled hardware/engine ranking or an equal-quality claim.

The pinned Halogen README reports 52.5 tok/s MTP across its ten prompt shapes
for 0.14.1, at about 85 W native Linux package power. Its updated HTTP prefill
reference is 1502 tok/s at pp8192 with cache off; it is not a pp2048 number.
Those references are not represented as 0.15.0 measurements.

A first-hand Reddit Vulkan report quotes 49.56 +/- 1.73 tok/s for Orca
Q4_K_M and 43.59 +/- 2.94 for Unsloth UD-IQ4_XS at short pp512/tg512, with
adaptive MTP. Different weights, generation length and code prompts prevent
an exact head-to-head comparison with this pp2048/prose/tg128 sweep.

## Evidence and reproduction

[Machine-readable results](halogen0150-pp2048-20260929.json) preserve original,
calibrated and Windows whole-request statistics, source pins, prompt hashes and all 102 retained per-request samples.

Full raw samples, the diagnostic driver, calibration inputs and rejected
instrument/admission attempts remain in the backend's ignored local benchmark
folder `backends/halogen-wsl2-0.15.0/.local/benchmarks/pp2048-20260929-215841/`.
The first one-token instrument check assumed a decode interval existed; that
assertion was corrected before the retained measurements. A one-token PP probe
has no measured post-first-token decode window and is never scored as TG.
No authenticated cloud-instance benchmark or separate SSE arrival-time decode
measurement is claimed in this run. The retained end-to-end wall time is HTTP
request time, not decode-only time. No old-version runtime was rebenchmarked.
