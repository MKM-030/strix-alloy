# Confirm the native conversation start before accepting its input boundary

Marcel authorized autonomous repair of the Voice assistant, authenticated login and model/capability maintenance. This small correction follows that authorization in the existing `codex/voice-repair-20261102` checkout.

The [official Bot API](https://www.servicenow.com/docs/r/api-reference/rest-apis/bot-api.html) specifies `syncResponse:true` for `START_CREATED_CONVERSATION` to avoid startup races. The installed handler supports it. Current `voice/bridge.py` omits it and accepts only an enqueue acknowledgement. The installed `VABotToBotSyncResponseBuilder` can instead return either an empty success acknowledgement or actual rich controls without a `status` key. Adding the flag alone would reject a valid response.

Use synchronous confirmation for this one startup action. Leave normal turns and END on their current asynchronous paths. Feed actual synchronous controls through the same matched-output/deduplication/state transition used by callbacks. Empty success confirms transport only: it must continue waiting for a real input control. Bind a content response to the exact outstanding startup request, user and any supplied session identifier; reject errors, malformed controls, stale/mismatched identities and contradictory acknowledgements without retry. A callback may arrive before the HTTP response; both orders must preserve one input boundary, one startup and existing shutdown ownership.

Alternatives considered: flag-only is invalid for native content replies; making all turns synchronous would change the intended asynchronous dialogue; replacing B2B with the Background Channel still lacks a complete response/continuation transport. The chosen change is confined to the documented bootstrap contract. It does not establish that the native worker's effective user is repaired, or guarantee a device latency improvement.

No credentials, transcript or server response payload may be newly logged. Preserve caller-ticket retirement, CREATE validation, native profile/model selection, independent greeting, name confirmation, callback authentication, capacity and uncertain-delivery cleanup. Do not execute auth/native/model/audio/business operations or restart services as part of implementation. Live acceptance is a later separate step after source review.

Verification must exercise real local aiohttp transport and Bridge state with synthetic fixtures: direct and `result`-wrapped content; empty success; wrong request/user/session; malformed/error reply; callbacks before and after the HTTP response; cancellation/END while startup is pending; subsequent ordinary turn stays asynchronous. Existing native lifecycle and startup-overlap coverage must remain passing. Preserve tests and receipts of prior live attempts.
