## Parameters and behavior

- Switch script: `apply`, explicit `allCapabilities` or `capabilityIds`, `targetModel`, optional provider/model registration IDs to resolve ambiguous names, `includeInactive` (false), `allowAdminMaintenance` (false). Default preview performs no writes. Scope all means eligible Custom LLM graphs, with an explicit report of excluded/missing/protected capabilities. Active/published usage prompts remain distinct; preserve provider selection, filters, prompt text/schema/validators and inactive alternatives.
- Add script: selected `capabilityIds`, registered `targetModel`, source-definition overrides, target provider/profile/alias as needed, `apply` false and optional explicit administrative maintenance. Prepare provider-specific definitions, prompts and native bindings beneath existing capability identities. New model configuration is additive and idempotent; existing model alternatives and deliberate edits are retained. Defaults are preserved unless separately requested in parameters and covered by explicit checks.
- Resolve a registered model and its provider/API contract before writing. Gemma, Halogen and other registered names are parameters. These scripts configure ServiceNow metadata; model loading remains a separate controller operation.
- Read schema/identity/ownership before any mutation. Preflight the whole selection, then write only intended eligible own metadata. Reject ambiguous or unsupported relationships rather than cloning protected system fields or guessing schemas. Recheck revisions around writes and report partial outcomes honestly; do not claim transactional rollback from revision checks.
- Preserve calculated `request_tokens` behavior, credentials/connection aliases, transformers, native generated relationships and no-delete capture. No role/ACL changes or business-rule suppression. Administrative record writes, when explicitly enabled, require admin and remain limited to unprotected customer configuration.
- Model History is a first-class graph/lineage requirement. Native schema and source behavior must establish its actual relationship. New configuration receives correct target-model lineage; do not transplant source Now LLM identity/version ancestry into the target. Existing source/vendor audit history is preserved. Exact behavior will follow the native audit, not an invented history table.
