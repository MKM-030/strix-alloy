## Chosen path and bounds

Use stock llama.cpp b10690's `POST /v1/chat/completions/input_tokens`, then at most one `POST /v1/chat/completions`. Both receive the same immutable complete JSON body, with explicit system/plain user messages, existing schema, temperature0, max_tokens24 and cache_prompt=false. The count endpoint is fixed to the same literal loopback host/port. No endpoint fallback, retries, repair, redirects, model hot-swap or estimate.

This replaces one HTTP request with **one count attempt plus at most one inference attempt**. It remains one inference. Version the admission protocol `pinned_chat_count_v1`; expose separate request-owned count/inference/total HTTP attempt counts. Local bypass/byte rejection uses0/0/0; count rejection/failure1/0/1; admitted model path1/1/2. An attempted send with unknown outcome consumes its count.

Require strict count JSON with object=response.input_tokens and an integer input_tokens in1..3584, excluding bool. Count3585+ returns context_budget without inference. Count+24 must fit4096. Retain caller4000characters, context12000UTF8bytes, options70, envelope8192bytes, decoded content64bytes. Every competitor and the complete original caller/objective/description/question must be preserved or the request rejected, never silently pruned/truncated.

The existing16384byte bound is ratified as **per complete HTTP request** (request line, explicit actual headers and body), not the sum of two requests. Both endpoints must fit; record aggregate transaction bytes separately. Do not log Authorization or content. Make Host, Content-Length and any other emitted headers explicit so accounting matches actual framing; avoid hidden default headers. Existing body cap also remains16384.

The whole model path, beginning before request preparation and ending after response validation, shares one monotonic2s deadline. Route p95<2s/max<=2.2s includes admission. Do not allocate another2s to inference after counting. Auth loading, serialization, socket connect/write/read, count/choice parsing and observer work all consume this same deadline. No repeated per-fragment full allowance.

Require inference usage.prompt_tokens equal admitted count, completion_tokens an integer0..24, and finish_reason=stop. Missing/mismatched usage or context rejection is admission disagreement/unavailable, never a valid route; length is incomplete output/schema clarification. The pre-inference count remains the real gate; posthoc usage equality is corroboration. Existing choice/schema/binding/policy/Store guards remain.

## Ownership, cancellation and diagnostics

Keep a request-private transport state, immutable payload and catalog hash, absolute deadline, cancellation event and closable connection. No shared mutable last-request receipt. Preserve public classify/classify_prepared return and Route/coordinator APIs. A narrow private request-observer/subclass hook may expose immutable per-request admission snapshots to later evaluator/acceptance owners; it must not convey content or authority, and telemetry must not permit an extra send.

Cancellation must retire/seal inference dispatch after a late/failed count; asyncio task cancellation alone does not stop a thread. Use a brief request-private synchronization point for cancellation versus inference dispatch, an absolute-deadline check at dispatch and explicit attempted-state semantics. Do not hold a blocking network operation under a lock awaited on the event loop. Close/retire owned sockets at timeout/cancel; retain honest outstanding-worker cleanup state. A worker that returns a count after terminal cancellation cannot initiate inference. A response after the deadline cannot be accepted, rebound or published. No new replacement attempt from cleanup.

Prefer one request-owned HTTP connection for the sequential transaction; loss between count and inference fails closed rather than transparently reconnecting. Bound complete response framing; partial JSON prefixes and trickle reads cannot complete admission early or reset the deadline. Always balance/retire owned resources. These client guarantees do not prove server slot release; Task17 sharing requires separate real runtime evidence.

Ordinary diagnostics are bounded enums/counters/hashes only. Distinguish admission stage/reason, exact count nullable, count validity nullable, payload binding, usage-count match nullable, attempts and per-phase timing. Keep bypassed choice/schema/policy stages null. context_budget is not malformed model JSON. Error mapping: over-count=context_budget; malformed/unavailable count=unavailable; either phase expires=timeout; usage disagreement=unavailable; incomplete output=schema. Preserve existing ProposalObservation meanings; no false semantic correctness.
