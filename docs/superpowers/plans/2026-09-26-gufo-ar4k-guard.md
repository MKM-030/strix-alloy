# First guarded native GUFO AR4k smoke implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. This document plans code and offline verification; it does not authorize a model load.

**Goal:** Build one fixed, parent-owned, guarded native Windows GUFO AR4k smoke that can make one small authenticated completion, stop its owned server, and prove or explicitly fail cleanup.

**Architecture:** A fixed profile and provenance store qualify the exact model, build, app-local runtime, operator sequence and reviewed margin. A pure smoke policy applies the 68/4/20 GiB allowance to existing scoped telemetry. A foreground guardian reuses the reviewed suspended Windows Job Object, exclusive lock, query watchdog, baseline and recovery primitives, and polls the independently implemented HTTP worker without letting HTTP block owned-process stop. Every attempt preserves evidence and a permanent one-attempt marker; uncertain cleanup also preserves the incomplete latch.

**Tech stack:** Python standard library, Windows PowerShell telemetry already implemented, existing `unittest` fixtures, `gufo_control` modules. No dependency or GUFO source change.

The HTTP interface agreed with its independent work item is `start_smoke(*, api_key: str, startup_deadline: float, lifetime_deadline: float, cancel: threading.Event | None = None) -> SmokeTask`. `SmokeTask.done` and `.cancel` are Events; `.result` is JSON-serializable only after `.done`. There is no live ready/POST progress interface. The guardian calls it once after resume, polls `done.is_set()` beside telemetry, signals `.cancel.set()` on any abort, closes the owned child promptly, then allows only the remaining finite cleanup interval for `.done`. The HTTP worker enforces its own 480 s startup and 60 s POST bounds; the guardian independently enforces 600 s process lifetime and memory limits. `post_attempted` becomes true before the one POST; a failed POST is consumed. The worker's absolute socket deadlines and `finally: done.set()` are specified in `reports/gufo-smoke-http-plan-20260926.md`.

The store interface should be `verify_static() -> dict` (full pinned manifest and current stamps), `recheck_static(manifest: dict) -> None` (cheap stamp/source/model-directory recheck), `load_original_operator_baseline() -> Baseline`, `begin_run(run_dir, manifest, baseline) -> None`, and `finish_run(run_dir, result) -> None`. Full fixed hashes and bounded GGUF metadata are checked once before final telemetry. A changed stamp during final telemetry, creation or pre-resume is an immediate refusal; do not rehash large files and let freshness expire. A separate qualification record for this exact profile binds source, exe, model revision/descriptors, 68/4/20/49/24/12 bounds, operator result hashes, the accepted conditional margin report SHA-256 `CD55B870D7301398BB55665D57338BE1EA55668A52C5FCE50438A86EC583CD20`, and a nonempty independent guard-review ID. The code's default is unqualified until that guard review; the numerical margin decision is already accepted. The public CLI accepts no path or arithmetic overrides.

The policy interface should be `admission_reasons(profile, original_baseline, frame, *, now, now_utc) -> list[str]`, `runtime_reasons(profile, original_baseline, frame, owned, *, now, now_utc) -> list[str]`, and `recovery_reasons(original_baseline, frames) -> list[str]` (the last can delegate directly). The owned inventory helper must return a copy of the snapshot for policy checks, preserving the raw frame in JSONL. It removes exactly one PID from `other_inference_pids` only when that PID equals `owned.identity['pid']`, `owned.verify_live_identity()` succeeds, and the live handle identity equals the recorded PID, creation time and executable; any other listed PID refuses/aborts. No name-based blanket exclusion and no acceptance of an exited, reused or stale PID. Prelaunch and recovery frames have no exclusion. Annotate the policy copy and saved decision with excluded PID and proof status.

Recheck integration clarification: `recheck_static(manifest, *, current_run=None)` remains strict before admission and inside `begin_run`: any existing smoke marker refuses. After `begin_run`, the guardian supplies its exact `run_dir` as `current_run` while continuously holding both locks. This path must validate both bounded marker files against that exact root-contained run, profile and original baseline, and the persisted run manifest against the supplied verified manifest; missing, mismatched or another run's markers refuse. Static artifacts are still stamp-checked without large rehashing. This adds no retry, limit override or broader launch authority.

## Self-review and handoff
