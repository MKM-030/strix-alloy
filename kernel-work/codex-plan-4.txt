## 4. What I already established (don't redo)

1. **`--spec-draft-p-min 0.0` is correct.** The FR-Spec draft logits are uncalibrated; any threshold
   throws away acceptance for nothing (vincentkelleher's compose says this explicitly).
2. **`-md` must be passed** �?" sidecar auto-discovery does not search the `MTP/` subfolder.
3. **`--load-mode dio`** (O_DIRECT) is what the validated config uses.
4. **`GGML_VK_DISABLE_GDN_CACHE_FUSION=1`** �?" vincentkelleher's compose sets this because the branch's
   fused GDN state-cache path **corrupts output on the 8060S**. I ran with it at 131k and it was clean.
5. **Froggeric's template fixes a reported "80 % inference throughput drop on llama.cpp"** (flattened
   Jinja AST) and preserves think-blocks for KV-cache hits. It also defaults reasoning to **medium**
   instead of `xhigh`.
6. **The 0 %-acceptance rows we both saw were a prompt-cache artifact**, not a depth property �?" and my
   first two explanations (depth, first-request) were both wrong. Do not build on them.
7. **The `per_layer_token_embd` / PLE table is paged, not resident** �?" your inventory: 26.82 GiB,
   IQ4_NL, 320M rows. This is why RAM does not grow with context on the Vulkan path.

#!/usr/bin/env python3
"""Token-exact Flash-Next benchmark client for llama-server (Windows or WSL).

Measures PREFILL and DECODE at exact prompt token counts using /tokenize sizing and
/completion with cache_prompt=false, reading llama.cpp's `timings` block.

Usage:
  python fnbench.py --port 8113 --label vulkan-frspec --sizes 1024,8192,32768,65536,131072 \
      --gen 128 --repeats 3 --out results/vulkan-frspec.json

Notes:
  * Prompt cache is disabled per request so prompt_n is a true fresh prefill.
  * Server must be started with -c >= max(size)+gen+margin.
  * MTP acceptance (draft_n_accepted) is captured when present.
"""
import argparse

import os
import sys

import urllib.request

HERE = os.path.dirname(os.path.abspath(__file__))
CORPUS = os.path.join(HERE, "bench-corpus.txt")
TOKENS = os.path.join(HERE, "bench-tokens.json")


def http_json(url, payload=None, timeout=7200):
    data = None
    if payload is not None:
        data = json.dumps(payload).encode("utf-8")
    req = urllib.request.Request(url, data=data,
                                 headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=timeout) as r:
        return json.loads(r.read().decode("utf-8"))


def build_corpus(min_tokens_hint=300000):
    """Concatenate repo docs into a natural-language corpus large enough for 128k+ prompts."""
    if os.path.exists(CORPUS) and os.path.getsize(CORPUS) > 2_000_000:
        print(f"corpus exists: {os.path.getsize(CORPUS)/1e6:.1f} MB")
        return
    roots = [
        r"C:\Projects\REV-N-ornith-eval-20260911\docs",
        r"C:\Projects\REV-N\docs",
    ]
    chunks = []
    for root in roots:
        for ext in ("*.md", "*.txt"):
            for p in glob.glob(os.path.join(root, "**", ext), recursive=True):
                try:
                    with open(p, "r", encoding="utf-8", errors="ignore") as f:
                        t = f.read()
                    if len(t) > 500:
                        chunks.append(f"\n\n=== {os.path.basename(p)} ===\n\n{t}")
                except Exception:
                    pass
    text = "".join(chunks)
    # augment with varied synthetic prose so decode is not degenerate and length is sufficient
    para = ("The system processes each request in order, recording the measured latency and the "
            "aggregate throughput for every stage of the pipeline. Operators review the resulting "
            "tables, compare them against the published reference figures, and adjust the batch "
            "sizes until the observed numbers converge on a stable plateau. ")
    i = 0
    while len(text) < min_tokens_hint * 4:  # ~4 chars/token
        text += f"\n[section {i}] " + para
        i += 1
    with open(CORPUS, "w", encoding="utf-8") as f:
        f.write(text)
    print(f"corpus built: {len(text)/1e6:.1f} MB -> {CORPUS}")


def tokenize(port, text):
    r = http_json(f"http://127.0.0.1:{port}/tokenize", {"content": text})
    return r["tokens"]


def get_token_pool(port, need):
    """Tokenize the corpus once; cache token ids. Return list of >= need tokens."""
    if os.path.exists(TOKENS):
        try:
            pool = json.load(open(TOKENS))
            if len(pool) >= need:
                print(f"token pool cached: {len(pool)} tokens")
                return pool
        except Exception:
            pass
    build_corpus()
    with open(CORPUS, "r", encoding="utf-8", errors="ignore") as f:
        text = f.read()
    print(f"tokenizing corpus ({len(text)/1e6:.1f} MB)...", flush=True)
    pool = tokenize(port, text)
    print(f"tokenized -> {len(pool)} tokens")
    json.dump(pool, open(TOKENS, "w"))
    return pool


def wait_ready(port, timeout=1800):
    t0 = time.time()
    while time.time() - t0 < timeout:
        try:
            with urllib.request.urlopen(f"http://127.0.0.1:{port}/health", timeout=5) as r:
                if r.status == 200:
                    return True
        except Exception:
            time.sleep(3)
    return False

**Q2. WSL costs: real mechanisms, unmeasured attribution**

WSL adds the Linux guest, DXG bridge, VM memory accounting and guest/host synchronization to the execution environment. GPU communication crosses the DXG path into Windows’ driver stack. Native Windows removes that guest path but still uses Windows GPU scheduling and memory management. [AMD’s WSL architecture](https://rocm.docs.amd.com/projects/amdsmi/en/develop/how-to/amdsmi-wsl-mode.html)

Possible contributors to your gap include:

- Submission and synchronization overhead.
- Different HIP runtimes, compiler output and kernel dispatch.
- Allocation, residency, paging and host-memory pressure.
- PLE access through different filesystem and mapping paths.
- Power, thermal and desktop contention.

**You have not measured their individual contributions.** In particular, the comparison changes machine configuration and carve as well as operating environment. “WSL costs 32%” is not established.

The hardware specification is broadly sound, with one correction: gfx1151 supports **wave32 and wave64**; wave32 is a kernel execution choice, not the only available wave size. [AMD specifications](https://rocm.docs.amd.com/en/docs-7.14.1/reference/gpu-specs.html)

For this workload, WSL’s remaining value is development convenience and reproducing Linux-oriented source behavior. Given six reported VM restarts, it should no longer be the primary heavy-benchmark lane.

1. VS 2022 Build Tools and Windows SDK, with the MSVC environment active.

4. The Windows lazy-reader `prefetch` stub where absent.
5. A consistent source-level HC16 workaround on the gate-free branch.
6. Matching HIP/BLAS runtime DLLs and kernel-library directories, verified without accidental SDK dependencies on `PATH`.

The existing [Windows build recipe](https://github.com/olliehm/qwen-flash-next-windows/blob/main/docs/build-engine-windows.md) provides the toolchain and packaging procedure. **[ESTIMATE]** Allow **1–3 hours** if the SDK is already available; a guaranteed 45-minute migration is optimistic.

**Q2. WSL costs: real mechanisms, unmeasured attribution**

Possible contributors to your gap include:

- Submission and synchronization overhead.
- Different HIP runtimes, compiler output and kernel dispatch.
- Allocation, residency, paging and host-memory pressure.
- PLE access through different filesystem and mapping paths.
- Power, thermal and desktop contention.

**You have not measured their individual contributions.** In particular, the comparison changes machine configuration and carve as well as operating environment. “WSL costs 32%” is not established.
